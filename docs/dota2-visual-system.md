## 0. 设计定位

### 0.1 三个关键词

**安静 · 神秘 · 温暖，带一点游戏感。**

- **安静** —— 深色底、低对比的面板、大片留白。数据自己会说话，界面不抢话。
- **神秘** —— 光从容器里透出来，不是照在容器上。石与金属的材质，而不是霓虹。
- **温暖** —— 金色与余烬色。冷色只用来表示「还在动的东西」。
- **一点游戏感** —— 切角、浮雕、斜切铭牌、稀有度缎带。有份量，但不做作。

### 0.2 参照对象

| 参照 | 取什么 | 不取什么 |
|---|---|---|
| Dota 2 主界面（Dashboard） | 英雄面板 + 侧栏的构图、面板的重量感、进入的节奏 | 英雄立绘、动态背景、技能栏 |
| Dota 2 英雄选择（Hero Grid） | 筛选侧栏 + 肖像网格 + 悬停预览的三段式、宝物格的框 | 英雄数值、定位筛选 |
| Dota 2 战报 / 赛事面板（Match Panel） | 横向对齐的列、序号徽标、宽面板的仪式感 | 队伍配色、比分动画 |

**只借鉴手艺，不借用任何素材。** 本项目不使用、不下载、不仿制任何 Dota 的图片、字体、音效或
界面切图。下面的所有几何、颜色、动效都是重新设计的结果。

### 0.3 三条刻意的例外

Dota 的视觉语言里有一部分，搬到这个产品上会直接违反产品边界。这三处**必须**改：

| Dota 的做法 | 本项目的做法 | 原因 |
|---|---|---|
| 猩红 = 敌方阵营 | 猩红（`--color-alert-stop`）= **只有硬错误**。敌方红整条带被换成琥珀与余烬色 | 本产品没有「敌方」这个概念。红色是留给操作失败和请求失败的全站唯一红色 |
| HUD 血条 / 蓝条往 0 走 | **全站没有任何往 0 走的进度条。** 每一条计量条都朝「稀有」那一端填充 | 「死亡倒计时」式视觉被明确禁止（v1 §1.2）。一条正在耗尽的条会被读成「这个仓库正在死去」，而本产品只陈述事实 |
| 亡灵、墓碑、骨骼 | 石 + 锻金。材质语言是纹章式的金属与石头 | 禁止词表：墓碑、骷髅、坟土、乌云、闪电、破碎玻璃、乌鸦 |

## 1. 材质语言

| 材质 | 出现在哪 | 怎么做的 |
|---|---|---|
| **石（Stone）** | 面板、卡片、榜单 | 暗面（`--color-surface-panel` `#1E211D`）+ 极淡颗粒（不透明度 0.035 的 `feTurbulence` 噪声）。颗粒只落在表面上，文字压在表面上，绝不压在颗粒上 |
| **金属（Metal）** | 描边、铭牌、角标、缎带 | 1px 金色描边（`--color-gold-soft`）+ 顶部一道 1px 的白色高光（不透明度 0.05），读作「凸起的金属」 |
| **虚空（Void）** | 整页背景 | 近黑的绿（`--color-bg-base` `#0C1211`）+ 页面最外层一道径向暗角（中心透明 → 边缘 38% 黑） |
| **金（Gilt）** | 名称、序号徽标、传说的框 | `#C9A227`，亮一档是 `#E4C463`。金色只用在「值得被看见」的地方 |

**没有羊皮纸。** 浅色纸面会破坏 v1 §七 要求的「深色、安静」，也会让本站变成两套对比度体系。

**颗粒的实现**（`src/frontend/styles/global.css`）：

```css
/* 内层自己成一个层叠上下文，负层级才不会掉到面板底下。 */
.cut-frame__inner.grain {
  isolation: isolate;
}

.cut-frame__inner.grain::before {
  content: "";
  position: absolute;
  inset: 0;
  z-index: -1;
  pointer-events: none;
  background-image: url("data:image/svg+xml,…feTurbulence…");
  opacity: var(--layer-grain-opacity);   /* 0.035 */
}
```

颗粒是内层的 `::before` 且 `z-index: -1`，不是外层的 `::after`：伪元素是最后一个子元素，
`::after` 会画在文字**上面**，与上表「文字压在表面上，绝不压在颗粒上」相反。

## 2. 面板几何

### 2.1 切角（cut corner）

Dota 面板的招牌：左上与右下各切一个角。

```css
clip-path: polygon(
  var(--cut) 0,
  100% 0,
  100% calc(100% - var(--cut)),
  calc(100% - var(--cut)) 100%,
  0 100%,
  0 var(--cut)
);
```

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--cut-xs` | 6px | 小徽标、标签 |
| `--cut-sm` | 10px | 次级面板、筛选栏、榜单 |
| `--cut-md` | 14px | 卡片、侧栏 |
| `--cut-lg` | 20px | 主面板 |
| `--cut-xl` | 28px | 落地页首屏 |

### 2.2 描边不是 border

`clip-path` 会把 `border` 一起切掉，切角处就没有描边了。所以描边用**两层同路径裁切**实现：

```
┌─ 外层 ────────────────┐  背景 = 描边色，裁切路径 = --cut
│  ┌─ 内层 ──────────┐  │  背景 = 面板色，裁切路径 = --cut（同一形状）
│  │                 │  │
│  │      内容        │  │  内层比外层小 1px → 切角处露出一道楔形金属边
│  │                 │  │
│  └─────────────────┘  │
└───────────────────────┘
```

实现见 `.cut-frame` / `.cut-frame__inner`（`src/frontend/styles/global.css`）。

### 2.3 圆角

站点其余部分几乎不用圆角 —— 切角已经是本站的几何语言，再叠圆角会打架。

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--radius-xs` | 2px | 徽标、序号 |
| `--radius-sm` | 4px | 按钮、输入框、芯片 |
| `--radius-md` | 8px | 提示条 |
| `--radius-lg` | 12px | 预留 |
| `--radius-xl` | 16px | 预留 |
| `--radius-pill` | 9999px | 药丸标签 |

### 2.4 角标托架

主面板与抽屉的四角各有一枚金色 L 形托架（`.corner-brackets`），不透明度 0.55，宽高 14px。
只出现在主面板和落地页首屏 —— 到处都是就等于哪里都不是。

### 2.5 网格与留白

| 项 | 值 |
|---|---|
| 基础间距单位 | 4px（Tailwind 的 `p-1` = 4px … `p-24` = 96px） |
| 页面容器最大宽 | 1200px（`--container-page`） |
| 页面左右安全边距 | 24px（≥640px）/ 16px（<640px） |
| 栅格列数 | 12 列（≥1024px）/ 8 列（768–1023px）/ 4 列（<768px） |
| 列间距 | 24px（桌面）/ 16px（平板与手机） |
| 区块之间 | 48px（桌面）/ 32px（移动） |
| 卡片之间 | 16px（桌面）/ 12px（移动） |

### 3.2 颜色纪律

1. **`--color-alert-stop` 是全站唯一的红色**，只出现在操作失败与请求失败。业务上的「沉睡」一律不用红色，也不用任何暖警示色系。
2. **未知态不用琥珀色。** 琥珀 = 「需要你注意或行动」；未知 = 「我们没读到」。两者语义不同，混用会让限流提示失效。
3. **禁用态不是灰色遮罩**，而是 `opacity .45` + `cursor: not-allowed`，并且**始终保留 1px 描边** —— 没有描边的灰块会被误读成「未知」。
4. **休眠标签不用彩虹色。** 每类标签绑定固定语义色，颜色是冗余编码：文字永远在。
5. Tailwind 自带的色板在本项目里被整体关闭（`--color-*: initial`）。只有本文件列出的颜色存在。

## 4. 稀有度阶梯

### 4.1 规则

> **沉得越久，越稀有。**

稀有度由**沉睡天数**派生。它是一个关于时长的**事实**，不是评价。

| 等级 | 沉睡 | 边框 | 缎带 | 计量条 |
|---|---|---|---|---|
| **普通** | < 181 天 | 灰绿细边 | 无扫光 | 短 |
| **稀有** | 181–364 天 | 青绿边 + 内发光 | 无扫光 | 中 |
| **史诗** | 365–1094 天 | 蓝紫边 + 内发光 | 无扫光 | 长 |
| **传说** | ≥ 1095 天 | 金边 + 外辉光 | 金色扫光 | 满格 |

**边框与辉光怎么落地：**

| 部位 | 变量 | 画法 |
|---|---|---|
| 描边 | `--rarity-legendary` / `--rarity-epic` / `--rarity-rare` / `--rarity-common`（卡上的 `--rarity-edge`） | 切角框那一圈 1px 外缘 |
| 内发光（稀有 / 史诗） | `--rarity-rare-glow` / `--rarity-epic-glow`，半径 `--rarity-glow-blur` | 卡内的 `inset` 阴影 |
| 外辉光（传说） | `--rarity-legendary-glow`，半径 `--rarity-bloom-blur` | 卡外的 `drop-shadow` |

两种辉光不叠加：一张卡上只该有一圈光。普通档没有辉光变量，所以就是没有。

阈值取自 `src/shared/thresholds.ts`，与交互规范 §5.2 的休眠标签边界**完全一致**：

| 等级 | 沉睡 | 对应的休眠标签（§5.2） |
|---|---|---|
| 普通 | < 181 天 | 无（仓库还在动） |
| 稀有 | 181–364 天 | 刚刚安静 |
| 史诗 | 365–1094 天 | 深度待机 |
| 传说 | ≥ 1095 天 | 时间胶囊 |

**为什么等级与标签是两套词？** 稀有度是**收藏**的框架（这件东西有多难得），休眠标签是**状态**的描述
（它现在怎么样）。同一件东西，宝物格给一个稀有度，标签行给一个状态 —— 这正是 Dota 宝物卡的读法。
两者永远一致，但说的不是同一件事。

### 4.2 三条纪律

1. **等级词永远渲染。** 缎带上写着「传说」。颜色只是冗余编码 —— 去掉颜色，这段文字依然完整可读。
2. **未知不给等级。** 沉睡天数读不到时，卡片没有缎带，天数显示 `? 未知`。**绝不**退化成「普通」—— 那等于把「没读到」说成「刚睡下」。
3. **计量条只朝稀有端填。** 满格是「传说」，不是「危险」。传说是最满的一格。

### 4.3 稀有度 ≠ 评价

稀有度只回答「多久没动了」。本站**不会**因此说：

- ❌「这个项目已经失败了」
- ❌「上游已经死了」
- ❌「你的改动全都合并了」
- ❌「你最懒的开发者」

稀有度是稀有度，不是分数。榜单里出现「传说」时，读的是「它沉了很久」，不是「它很糟」。

### 4.4 另一根轴：充能等级

本站有**两根轴**，它们互相独立，绝不混用：

| 轴 | 标注的对象 | 由什么派生 | 出现在哪 |
|---|---|---|---|
| **稀有度**（§4.1） | 一个**仓库** | 沉睡天数 | 仓库卡、榜单行 |
| **充能等级**（§6.3） | 一个**用户** | 带主题的公开仓库数 | 鉴定页英雄面板、首页藏品卡 |

**两根轴不共用颜色。** 如果充能等级也套上「传说」的金边，同一个金色就会同时说
「这个仓库沉了三年」和「这个人有 25 个仓库」两件事 —— 一眼看去是同一个意思。
充能等级只用 §6.3 列出的三个既有令牌，不借用任何稀有度变量（`--rarity-*`）。
充能条也一样：它走计量条的基础渐变（青 → 金），而不是传说档那条金色渐变（§6.3）。

**分开靠的是「形」，不是「色」。** 稀有度用**边、缎带与辉光**说话（仓库卡上的一枚等级牌）；
充能等级用**罗马数字 + 阶 + 星标**说话（面板上的一行刻度）。星标用的 `--color-gold`
与传说档的金边同值不碍事 —— 两者的**形状与位置**不会互相冒充。

**充能等级也不是评价。** 它回答「这个人收集了多少」，不回答「这个人做得多好」，
更不回答「这个人值不值得上榜」。它的措辞里没有 金 / 银 / 铜 —— 金属词读起来
像是对用户本人的一次材质判断，本站没有资格做这个判断（§4.3 的同一条纪律）。

## 5. 字体与排版

### 5.1 三套字栈

| 角色 | 字栈 | 说明 |
|---|---|---|
| 展示体 | `"Cinzel", "Trajan Pro", "Optima", "Noto Serif SC", "Source Han Serif SC", "Songti SC", "SimSun", serif` | Cinzel 是免费的 Trajan 同类字体。装了就用；没装则中文衬线栈接手 |
| 界面体 | `"PingFang SC", "Microsoft YaHei", "Noto Sans SC", system-ui, -apple-system, "Segoe UI", sans-serif` | 正文用界面体。工具的可读性比装饰性重要 |
| 等宽 | `ui-monospace, SFMono-Regular, "JetBrains Mono", Consolas, "Liberation Mono", monospace` | 仓库名、数值 |

**不加载任何网络字体。** 目标用户是中文读者，`fonts.googleapis.com` 对他们大多不可达。一个会静默失败的
webfont 比系统衬线体糟糕得多。

> 如果以后确实需要真正的 Dota 展示体，路径是**自托管一份子集 woff2** 到 `public/fonts/`，
> 并在 `@font-face` 里声明 `font-display: swap`。不要引入 CDN。

### 5.2 字阶

| 层级 | 字号 / 行高 | 字重 | 字距 | 用在哪 |
|---|---|---|---|---|
| Display | 38px / 1.15（移动 30px） | 600 | -0.02em | 落地页主标题 |
| H1 | 24px / 1.3 | 600 | 0 | 榜单抬头 |
| H2 | 20px / 1.3 | 600 | 0 | 面板抬头、卡片标题 |
| Body | 16px / 1.6 | 400 | 0 | 正文 |
| Body-S | 14px / 1.6 | 400 | 0 | 卡片说明 |
| Caption | 12px / 1.5 | 400 | 0.02em | 元信息、标签 |
| Micro | 11px / 1.45 | 400 | 0.02em | 缎带、序号、辅助标注 |
| Data-L | 30px / 1.1 | 600 | -0.02em | 沉睡天数 |
| Data-M | 20px / 1.2 | 600 | 0 | 统计数值 |
| Mono | 14px / 1.5 | 500 | 0 | 仓库名 |

**落地页口号的字号是 20px，不是 Display 的 38px。** 它用 **Display 字族**（`.display-cn`）配 **H2 字号**：Display 一级只留给落地页主标题，一屏放两个 38px 会互相抢；口号是品牌语，本来就该在主标题之下。字号决定层级，字族决定「这是品牌的声音」（交互规范 §M1.2 #11）。

### 5.3 两条中文专属规则

1. **中文标题不靠 `text-transform: uppercase`。** 汉字没有大写。Dota 的「宽字距大写」观感，
   在中文里用 `letter-spacing: 0.08em` + `font-weight: 600` 翻译（`.display-cn`）。
2. **拉丁文用 `.display-caps`** —— `text-transform: uppercase` + `letter-spacing: 0.22em`。
   它只用在 `SHELVES` / `URNS` 这类纯拉丁短词上。

### 5.4 数字

所有数字用 `font-variant-numeric: tabular-nums`（`.tnum`）。榜单的一列数字必须对齐，
否则读不出名次。

## 6. 图标与纹章

### 6.1 图标

- 1.5px 线性描边，尺寸 16 / 20 / 24px 三档。
- **不使用填充图标表达状态。** 填充会与「未知」混淆。
- 图标按钮必须有 `aria-label`。
- 图标颜色继承文字色（`currentColor`）。

### 6.2 纹章（sigil）

卡片的「肖像」位。我们没有美术资源，也没有使用任何美术资源的许可，但每张卡都需要一个
能一眼区分的锚点。

**做法：由 `owner/repo` 派生一个确定性的 SVG 图形。**

| 属性 | 规则 |
|---|---|
| 图形 | 8 个程序化字形：门 / 灯 / 拱 / 瓮 / 钥 / 眼 / 波 / 螺 |
| 色相 | 4 组：金 / 青 / 秘法紫 / 石灰 |
| 旋转 | 哈希决定的 15° 整数倍 |
| 确定性 | 同一个 `owner/repo` 永远得到同一个纹章 |
| 存储 | 无。不存任何资产，不发任何请求 |

**它不是头像。** 头像把注意力放在人身上，而本站的主语始终是仓库。

实现：`src/frontend/lib/sigil.ts`（FNV-1a 哈希）+ `src/frontend/components/card/Sigil.tsx`（绘制）。

### 6.3 充能等级标记（TierMark）

灵龛充能等级是**用户**的刻度线（§4.4）。标记由两样东西组成：**罗马数字 + 阶**，和一枚**星标叠层**。

| 档 | 仓库数 | 标记 | 星标 | 这一档在说什么 |
|---|---|---|---|---|
| 未启封 | 0 | 未启封 | — | 还没有仓库住进来。给一个公开仓库加上主题，它就会住进来。 |
| Ⅰ 阶 | 1–4 | Ⅰ 阶 | ★ | 灵龛刚点上火。 |
| Ⅱ 阶 | 5–9 | Ⅱ 阶 | ★★ | 已经攒下一点灰烬。 |
| Ⅲ 阶 | 10–24 | Ⅲ 阶 | ★★★ | 灰烬积成了堆。 |
| Ⅳ 阶 | 25+ | Ⅳ 阶 | ★★★★ | 充能完毕，随时准备为下一个项目注入生命。 |

**不用 金 / 银 / 铜。** 数字加阶后缀读起来是「一个阶段」，金属词读起来是「一种材质」——
后者是对用户本人的一次判断，本站不做这种判断（§4.3）。量级交给**星标叠层**：
星越多档越高，数字与星标互为冗余编码。

**Ⅳ 阶就是灵龛升级成「码之灵龛」的那一刻** —— Dota 里影之灵龛升级成魂之灵龛的那一下。
顶格之后没有下一阶，所以 Ⅳ 阶不画充能条，只写「充能完毕」。

#### 解剖

```tsx
<span className="inline-flex items-baseline gap-1">
  <span className="sr-only">灵龛充能等级 Ⅲ 阶</span>
  <span aria-hidden="true" className="font-display text-fg-primary">Ⅲ</span>
  <span aria-hidden="true" className="text-fg-secondary">阶</span>
  <span aria-hidden="true" className="text-gold">★★★</span>
</span>
```

| 部位 | 令牌 | 规则 |
|---|---|---|
| 罗马数字 | `--color-fg-primary`（Ⅳ 阶用 `--color-gold-bright`） | `.font-display`；未启封档没有数字，只写「未启封」 |
| 阶后缀 | `--color-fg-secondary` | 与数字同一基色，不另起一层颜色 |
| 星标 | `--color-gold` | `aria-hidden`；用 UI 字栈（每套中文 UI 字体都有 `★`，展示字栈不保证有） |
| 充能条 | `--color-teal` → `--color-gold`（计量条的基础渐变） | 见下方「充能条」；**刻意不等于任何一条稀有度渐变**（§4.4） |

**不新增任何令牌。** 这套标记完全由 §3 已有的令牌组合而成，所以 `npm run audit:design` 的令牌计数不变。

**可访问性两条是硬要求：**

- 数字、后缀、星标全部 `aria-hidden`，含义由一段**视觉隐藏的真实文字**承担
  （`灵龛充能等级 Ⅲ 阶`）。裸 `<span>` 上的 `aria-label` 会被读屏丢掉 ——
  这与 `UnknownValue` 是同一条发现。
- 等级**从不只靠颜色**。数字永远可见，星标数永远与数字一致；把所有颜色拿掉，一样读得出等级。

#### 充能条

充能条量的是**当前档内的进度**，不是「离下一档还差多远」。

- 量「离下一档的距离」会在每档起点恰好等于 0 —— 那是一条空条，与 §0.3「全站没有任何往
  0 走的进度条」和 §7.1 第 4 条直接冲突。
- 量「当前档」则是：Ⅰ 阶底 1/4，Ⅰ 阶顶满格。任何 ≥ Ⅰ 阶的档位，条子**永远不是空的**。
- 还差几个仓库，用**文字**写（`再收 3 个仓库升到 Ⅲ 阶。`），不交给条子一个人说。
  文字与条是**互补**的：条量的是当前档，说不出还差几个；文字还额外说出**升到哪一阶**。

充能条用**计量条的基础渐变**（`--color-teal` → `--color-gold`），**不是**任何一条稀有度渐变：
传说档是金 → 亮金，史诗是青 → 紫，稀有是青 → 青，普通是灰 → 灰。鉴定页上这两条条会同时出现 ——
同一个金色不能同时说「这个仓库沉了三年」和「这个人攒了 7 个仓库」（§4.4）。

| 档 | 区间 | 满档是 |
|---|---|---|
| 未启封 | [0, 1) | — （不画条） |
| Ⅰ 阶 | [1, 5) | 5 |
| Ⅱ 阶 | [5, 10) | 10 |
| Ⅲ 阶 | [10, 25) | 25 |
| Ⅳ 阶 | [25, ∞) | — （充能完毕，不画条） |

阈值取自 `src/shared/thresholds.ts`（`tierIMinRepos` / `tierIIMinRepos` / `tierIIIMinRepos` /
`tierIVMinRepos`），与交互规范 §M2.5 的表格**完全一致**。

**未知不给等级。** 仓库数读不到时，整个标记换成 `? 未知`：**不出现**数字、**不出现**星标、
**不出现**条子，也**不**退化成「未启封」—— 未启封是「0 个」的说法，而我们没有读到 0。

实现：`src/frontend/components/hud/TierMark.tsx`（标记）+
`src/shared/tier.ts`（派生：等级、档位、比例、还差几个、下一阶）+
`src/shared/ids.ts`（文案：`TIER_LABELS` / `TIER_COPY` / `tierAccessibleName` /
`tierNextStepCopy`）。

## 7. 动效

### 7.1 原则

1. **动效是反馈，不是装饰。** 每个动画都在回答「刚才发生了什么」。
2. **只动 `transform` 与 `opacity`。** 位置、大小、颜色一律不参与布局抖动。
3. **同一时刻最多两个动画在跑。**
4. **没有任何进度条往 0 走。** 计量条永远朝「稀有」那一端填充。
5. **降低动态效果逐模块降级**，不是全局一刀切。焦点环、错误提示、状态文字永远不受影响。

### 7.2 时长与缓动

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--motion-duration-instant` | 120ms | 颜色 / 透明度 / 描边反馈 |
| `--motion-duration-quick` | 160ms | 内容淡入淡出、列表重排 |
| `--motion-duration-fast` | 200ms | hover、焦点环、展开收起、标签切换 |
| `--motion-duration-modal` | 240ms | 抽屉 / 弹窗的弹入退场 |
| `--motion-duration-base` | 320ms | 卡片入场 |
| `--motion-duration-slow` | 480ms | 计量条填充 |
| `--motion-duration-shimmer` | 2400ms | 传说缎带的金色扫光 |
| `--ease-standard` | `cubic-bezier(0.4, 0, 0.2, 1)` | 通用（颜色、透明度、hover） |
| `--ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 进入类 |
| `--ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | 位移类 |
| `--ease-linear` | `linear` | 循环动画（扫光） |

### 7.3 动效表

| 时刻 | 效果 | 时长 / 缓动 |
|---|---|---|
| 面板入场 | 透明度 0→1 + 缩放 .985→1 + 上移 6px→0 | 320ms `ease-out` |
| 卡片悬停 | 上抬 2px + 边缘发光加强 | 200ms `ease-standard` |
| 卡片入场（网格） | 同面板入场，按索引错开 60ms | 320ms `ease-out` |
| 传说缎带 | 一道斜向金色渐变扫过 | 2400ms `linear` 循环 |
| 标签页切换 | 金色下划线横向展开 | 200ms `ease-in-out` |
| 吐司 | 上移 8px + 淡入 | 200ms `ease-out` |
| 计量条 | 宽度过渡到新值 | 480ms `ease-out` |
| 印记呼吸（仅落地页大印记） | 透明度 .86↔1 + 缩放 1↔1.035 | 6s `ease-in-out` 循环 |

**入场由容器承担。** `motion-panel-enter` 挂在面板与网格项上，卡片自己不再淡一次 ——
两层透明度相乘会把那 60ms 的交错糊掉。网格项用 `--stagger-1..5` 错开。

**「边缘发光加强」落在稀有度辉光上**：稀有 / 史诗是内发光，传说是外辉光，悬停时
半径 ×1.6。辉光是状态切换而不是动画 ——「只动 transform 与 opacity」这条规矩
管不到它，所以它瞬时切换，不参与过渡。

### 7.4 降低动态效果的降级矩阵

| 模块 | 正常 | `prefers-reduced-motion: reduce` |
|---|---|---|
| 面板入场 | 缩放 + 上移 + 淡入 | 只保留 120ms 淡入 |
| 卡片悬停 | 上抬 2px + 发光 | 只换描边颜色，不位移 |
| 传说缎带 | 金色扫光循环 | 扫光元素隐藏，保留静态金边 |
| 印记呼吸 | 呼吸循环 | 完全静止 |
| 标签页下划线 | 横向展开 | 瞬时出现 |
| 吐司 | 上移 + 淡入 | 只淡入 |
| 计量条 | 宽度过渡 | 瞬时 |
| 焦点环 / 错误 / 状态文字 | — | **完全不变** |

实现见 `src/frontend/styles/motion.css`。

- 前三名有名次徽标：金 / 银（中性灰）/ 铜（秘法紫）。第四名及以后没有徽标。
- 桌面最小宽度 46rem，小屏横向滚动。
- 标签页切换时金色下划线横向展开。

### 8.4 响应式总表

| 断点 | 宽度 | 布局 |
|---|---|---|
| `< 640px` | 手机 | 单列；抽屉变底部面板；表单单列 |
| `640–1023px` | 平板 | 两列或单列；网格 2 列；榜单横向滚动 |
| `1024–1279px` | 小桌面 | L1 两栏；L2 两栏（无预览） |
| `≥ 1280px` | 桌面 | L1 两栏；L2 三栏；L3 完整表 |
| `≥ 1536px` | 宽屏 | 页面仍锁 1200px，两侧留白加深 |

### 8.5 常驻提示条：不完整与陈旧

两种提示条都是**常驻**的，不是吐司。吐司会消失，而这两条消息消失之后，
用户就不知道自己看到的到底是不是全的、是不是最新的。

| 条 | 出现条件 | 视觉 | 标题 | 动作 |
|---|---|---|---|---|
| 不完整 | 信封 `completeness === "partial"` | 琥珀描边，标题 `text-alert-warn` | 「本次结果可能不完整」 | 「重新读取」 |
| 陈旧 | 读取时间 > `THRESHOLDS.staleAfterHours`（24h） | 发丝描边，标题 `text-fg-primary` | M2/M3「这是 X 天前的数据」；M5「榜单数据为 X 天前」 | 「重新读取」/「刷新」 |

两条纪律：

- **陈旧 ≠ 错误。** 内容不清空、不隐藏，只补一条说明。数据仍然真实，只是可能已经过时。
- **时间戳跟着数据一起弱化。** 新鲜用 `--color-fg-secondary`，陈旧转 `--color-fg-muted`。
  阈值只有一个来源：`THRESHOLDS.staleAfterHours`。

陈旧判定与时长文案在 `lib/freshness.ts`，阈值在 `shared/thresholds.ts`，
和界面上公开的说明是同一个数。

## 10. 可访问性

| 项 | 规则 |
|---|---|
| 对比度 | 所有前景色 ≥ 4.5:1（见 §3.3）；焦点环 ≥ 3:1 |
| 焦点 | `:focus-visible` 全局金色 2px 描边 + 2px 偏移，不依赖任何组件自定义样式 |
| 焦点顺序 | 与视觉顺序一致（筛选 → 网格 → 预览） |
| 焦点陷阱 | 抽屉与弹窗捕获焦点，关闭后**归还**给触发元素 |
| Esc | 只关最上层 |
| 地标 | `header` / `nav` / `main` / `footer` / `aside`，每个 `nav` 有 `aria-label` |
| 标题层级 | 每页一个 `h1`，其后不跳级 |
| 表格 | 榜单用 `<table>` + `<caption>` + `scope="col"` |
| 装饰 | 计量条、扫光、印记全部 `aria-hidden="true"`，数值由旁边的文字承担 |
| 未知 | 原因随字段一起读出（「Star 数未知：GitHub 没有提供这个值。」）。`? 未知` 是纯文本标记，原因用视觉隐藏的真实文本承载 —— 它出现在按钮里的卡片上，不能再套一层按钮 |
| 错误 | `role="alert"` + `role="status"` 分工：断言用于短提示，礼貌用于结果播报 |
| 吐司 | `aria-live="polite"` |
| 语言 | `<html lang="zh-CN">` |
| 动效 | 逐模块降级（§7.4），焦点环与错误提示不受影响 |

## 11. Tailwind 映射

Tailwind v4 是 CSS-first 的：`@theme` 里声明一次，同时得到 CSS 变量与工具类。

| 令牌 | CSS 变量 | 工具类 |
|---|---|---|
| `--color-gold` | `var(--color-gold)` | `bg-gold` `text-gold` `border-gold` |
| `--color-surface-panel` | `var(--color-surface-panel)` | `bg-surface-panel` |
| `--color-state-unknown` | `var(--color-state-unknown)` | `text-state-unknown` |
| `--color-fg-primary` | `var(--color-fg-primary)` | `text-fg-primary` |
| `--color-on-accent` | `var(--color-on-accent)` | `text-on-accent` |
| `--font-display` | `var(--font-display)` | `font-display` |
| `--text-2xl` | `var(--text-2xl)` | `text-2xl` |
| `--radius-sm` | `var(--radius-sm)` | `rounded-sm` |
| `--shadow-panel` | `var(--shadow-panel)` | `shadow-panel` |
| `--ease-out` | `var(--ease-out)` | `ease-out` |
| `--animate-ribbon-shimmer` | `var(--animate-ribbon-shimmer)` | `animate-ribbon-shimmer` |
| `--container-page` | `var(--container-page)` | `max-w-page` |

### 11.1 命名规则

Tailwind 的 `text-*` 同时吃两个命名空间：`--text-*`（字号）和 `--color-*`（颜色）。
所以颜色令牌不能叫 `--color-text-*` —— 那会生成 `text-text-primary` 这样的类名。

本项目的三条命名规则：

| 用途 | 令牌前缀 | 工具类 | 例 |
|---|---|---|---|
| 内容文字（正文 / 次要 / 弱化） | `--color-fg-*` | `text-fg-*` | `text-fg-primary` |
| 压在强调色上的文字 | `--color-on-accent` | `text-on-accent` | `text-on-accent` |
| 数字 / 统计值 | `--color-data-*` | `text-data-*` | `text-data-emphasis` |

### 11.2 默认主题被整体关闭

```css
@theme static {
  --color-*: initial;
  --font-*: initial;
  --text-*: initial;
  --leading-*: initial;
  --tracking-*: initial;
  --radius-*: initial;
  --shadow-*: initial;
  --ease-*: initial;
  --animate-*: initial;
  --breakpoint-*: initial;
  /* …本项目的令牌… */
}
```

组件里出现 `bg-slate-800`、`font-sans`、`rounded-lg`、`shadow-md` 都是缺陷 ——
颜色、字体、字号、行高、字距、圆角、阴影、缓动、动画、断点只能来自
`src/frontend/styles/tokens.css`。

`@theme static` 不是可选的：普通 `@theme` 会被 Tailwind 剪枝，把「没有被任何工具类引用」
的令牌从产物里删掉，令牌文件就不再是唯一来源。`static` 让本文件写下的每一个令牌
都无条件进入产物 CSS。`npm run build` 之后可以逐个核对。

### 11.3 组件 CSS 里不许出现的东西

| 禁止 | 改用 |
|---|---|
| 裸 hex（`#c9a227`） | `var(--color-gold)` |
| 手写时长（`200ms`） | `var(--motion-duration-fast)` |
| 手写缓动（`cubic-bezier(...)`） | `var(--ease-out)` |
| 裸 px 间距 | `var(--space-4)` 或 Tailwind 的 `p-4` |

裸 hex 由 ESLint 规则强制（`eslint.config.js` 里的 `no-restricted-syntax`）：
在 `.ts` / `.tsx` 里出现一个 hex 字面量就是一条 error。

**部署**：`wrangler.jsonc` 把 `./dist` 绑定为静态资源，`not_found_handling:
"single-page-application"` 提供 SPA 回退，`/api/*` 先走 Worker，D1 绑定名 `DB`。
没有 Node SSR，产物是纯静态文件。

**主题名是配置，不是字面量**：前端读 `VITE_REPO_TOPICS`，Worker 读 `REPO_TOPICS`，
两者都默认 `repo-vessel,urn-of-repos`（逗号分隔的列表，带任意一个即入龛），
解析规则只有一份（`src/shared/topic.ts` 的 `resolveRepoTopicList()`）。

**看每一种状态**：原型把产品的每一种状态都做成可达的 —— 一份只有好数据的原型
什么都证明不了。

| 地址 | 看到的 |
|---|---|
| `/u/alice` | 正常结果 |
