## 0.3 范围与非目标

**范围内（MVP）**：首页用户名查询 → 个人公开仓库读取 → 灵龛鉴定结果 → 趣味称号 → 三张代表卡 → 仓库列表与详情 → 三张公开榜单 → 入龛说明与收录状态检查 → GitHub 登录 → 仓库认领与隐藏 → 分享卡片生成。

**范围外（明确不做，UI 中不得出现入口）**：

| 不做 | UI 层面的处理 |
|---|---|
| 充能 / 积分 / 徽章 / 任务 / 打卡 | v1.1 只保留**灵龛充能等级**这一条刻度线（§M2.5）：由公开仓库数自动判定，用户**不能购买、不能刷、不能折算积分**。付费充能、积分、任务、打卡、连续天数一律没有 |
| 评论 / 点赞 / 投票 / 投稿 | 榜单条目只有「查看详情」「分享」，无互动计数 |
| 用户主页 | 无「我的主页」，登录态仅用于认领管理 |
| 私有仓库 / 组织仓库 | 输入组织名时立即拒绝并说明原因；不做扫描 |
| 仓库写操作 | 全站无任何指向 GitHub 写 API 的可点元素 |
| Agent / MCP / 自动代码提取 / AI 判断项目价值 | 不存在相关入口 |
| 工时估算 / 失败概率 / 最懒排行 | 数值区只有仓库数、天数、Star、Fork |
| 年度报告 / 回魂录故事 | 无任何报告生成入口 |

### 0.3.1 国际化位置（v1 只做中文）

| 项 | 决定 |
|---|---|
| 目标语种 | 简体中文 / 繁體中文 / English / 日本語 |
| 第一版交付什么 | ~~只有简体中文。语言切换、locale 路由、按语种拆分的配置属于后续独立任务（§A.3）~~ **已完成（2026-11-01）**：四种语言全部上线，默认英语；访客按浏览器语言自动选择，**页头不放语言控件**；登录用户在 `/manage` 选 ENGLISH / 中文 / 日本語，中文的简／繁由浏览器地区决定 |
| 第一版必须先做完的两件事 | ① **预留文字空间**：文案不得被截断、控件不得因固定宽度而裁字、标题不得依赖中文专属的硬换行；② **预留切分点**：站点级文案集中在共享层的文案表里，按语种拆分是数据改动，不是组件改造 |
| 硬性要求 | 语种切换**不得**改变任何数据口径、阈值、状态机或 ARIA 契约。本节只约束文字与布局 |
| 谁拥有剩下三种语言 | i18n 任务。本文档只定义「简体中文」的文案；繁中 / 英 / 日的译文由该任务产出 |

**「预留文字空间」的可检查规则**（实现时逐条对照）：

| 规则 | 判定 |
|---|---|
| 站点文案不得截断 | 面板标题、副标题、统计行等**文案**一律不截断；只有仓库描述（用户内容）与等宽标识符（`@login`）可以截断 |
| 控件不得固定宽度 | 带文字的按钮用 `min-width` 而非 `width`，文案变长时按钮变宽而不是裁字 |
| 标题不得硬换行 | 不得用 `<br>` 之类按中文断句写死的换行；用最大宽度约束让文本自然折行 |
| 文案表按语种可拆 | 站点级文案集中在共享层；`ids.ts`（按 id 的文案）与 `copy.ts`（站点文案）两张表一起按语种拆 |

**为什么现在就要做**：英语与日语的字符串普遍比中文长 2–3 倍，中文下「刚好放下」的排版在英语下会立刻溢出。等到 i18n 任务再回头修布局，要改的是十几个组件而不是一张表。

## 0.4 成功指标与观测口径

产品目标是**娱乐优先**，不是留存优先。以下指标对应 v4.1 §17，观测口径需在实现时确定。

| 指标 | 口径定义 | 建议目标（**待确认**） |
|---|---|---|
| 发起查询率 | 首页会话中提交过用户名 / 首页会话 | ≥ 35% |
| 查询成功率 | 返回可用结果的查询 / 总查询 | ≥ 92%（含降级可用结果） |
| 结果加载时间 | P75，从提交到 M2 骨架替换为内容 | ≤ 2.5s |
| 分享卡生成率 | 成功生成图片 / 到达 M2 的会话 | ≥ 18% |
| 分享链接有效访问 | 分享链接带来的会话 / 生成的分享链接 | ≥ 12% |
| Topic 复制次数 | 入龛页「复制 Topic」点击 | 无目标值（作为绝对量观测） |
| 收录仓库数 | 通过核实且未被隐藏的收录仓库 | 无目标值（绝对量） |
| 认领隐藏成功率 | 认领成功后完成隐藏或恢复 / 认领成功 | ≥ 80% |
| 误收录投诉 | 有效下架申请数 | 目标 **0** |
| 下架处理时间 | 申请 → 生效的 P90 | ≤ 24h |
| 状态核实失败率 | 核实请求失败 / 核实请求 | ≤ 2% |

**口径纪律**：**限流、失败、超时产生的空结果一律不计入「成功」**，也不得折算为「0 个仓库」。

## 0.5 术语表

| 术语 | 定义 |
|---|---|
| 灵龛鉴定 | 对某用户名一次查询产生的完整结果单元（称号 + 四项数据 + 三张代表卡） |
| 沉睡天数 | `读取时刻 − 最后推送时刻`，按自然日取整，最小 0 |
| 休眠标签 | 由 §3 M3.4 规则表生成的状态标签（刚刚安静 / 深度待机 / 时间胶囊 / 余烬未熄 / 远行的 Fork / 已归档）；文案以 §5.3 为准 |
| 收录 | 仓库满足「个人 + 公开 + 带**本站配置的主题**（§0.5.1）+ 本站已核实 + 未被隐藏」五项条件，进入候选池 |
| 认领 | 用户通过 GitHub 登录证明自己是某收录仓库的所有者，从而获得本站展示的管理权 |
| 灵龛充能等级 | 由「带主题的公开仓库数」自动判定的用户刻度线（未启封 / Ⅰ 阶 / Ⅱ 阶 / Ⅲ 阶 / Ⅳ 阶），规则见 §M2.5 |
| 未知 | 本次读取**未能获得**该字段（限流、超时、字段不存在、上游不可达），**不等于** 0 |
| 不适用 | 该字段对当前对象无意义（如非 Fork 仓库的「上游」） |
| 陈旧 | 该条数据的读取时间距当前超过 §5.4 规定的阈值 |
| 完整性标记 | 每个结果单元携带的 `complete / partial / failed` 状态，驱动全局提示 |
| 遮罩 | 覆盖在内容上、阻断交互的半透明层，用于模态确认 |

### 0.5.1 主题（Topic）是配置，不是字面量

仓库靠 **GitHub Topic** 入龛。这个 Topic **由部署方配置**，不是一个写死在代码里的字符串。

**一个部署支持多个主题**：值是逗号分隔的列表，一个仓库只要带有其中**任意一个**主题就算入龛。

| 项 | 值 |
|---|---|
| 默认值 | `repo-vessel,urn-of-repos`（新名在前，旧名在后 —— 改名不应丢掉已带旧主题的仓库） |
| 列表形状 | 逗号（`，` `;` `；` 与空白也接受）分隔；逐项归一后去重，最多 8 个；全部无效时回落到默认列表 |
| SPA 读取的环境变量 | `VITE_REPO_TOPICS` |
| Worker 读取的绑定 | `REPO_TOPICS`（Wrangler `vars`） |
| 解析规则 | 按分隔符切分 → 逐项：去除首尾空格 → 转小写 → 非法字符替换为 `-` → 连续 `-` 合并 → 去掉首尾 `-` → 截断到 35 字符（GitHub 上限）→ 丢弃空项 → 去重 → 截断到 8 项；列表为空时回落到默认列表。**只有这一份规则**（`resolveRepoTopicList()`），前后端共用 |
| 界面上的呈现 | 所有出现主题的地方（入龛说明页、榜单收录条件、复制主题动作）都渲染**解析后的列表**（「`repo-vessel` 或 `urn-of-repos`」），不得出现字面量；只有一项时按单项渲染 |
| 漂移风险 | SPA 与 Worker 各读各的环境变量，理论上可以不一致；两者的**默认列表来自同一个常量**，且 Worker 会在 `x-repo-topics` 响应头回带它解析后的列表以便一次请求即可核对。接口上线后，权威值应由响应体下发 |

**为什么**：主题是产品与 GitHub 之间的接缝。部署方换一套仓库做试点、换品牌词、或者同一份代码跑两个站，都不应该需要改代码。同时，**主题文案出现在多处**，只要有一处漏改，用户就会在两个页面上看到两个不同的主题名。

## 0.6 与通用 PRD 框架的差异说明

用户提供的通用框架面向「3D 营销落地页」，本产品不是该形态。以下为**逐项裁剪与替换**记录，避免实现阶段误用通用范式。

| 通用框架条目 | 本项目落地 | 替换理由 |
|---|---|---|
| 3D 产品展示组件 | **Canvas 2D 环境光动画**：灵龛容器 + 漂浮代码碎片光点，≤ 60fps | v4.1 §14.1 要求「不使用墓碑、骷髅、坟土」「柔和幽光代替恐怖氛围」；且首屏 LCP 必须是输入框，不是 3D 模型 |
| 鼠标跟随动效 | **仅**灵龛光点组做 ±6px 视差衰减跟随，桌面指针设备且未开启 reduced-motion 时启用 | 场景唯一，不构成核心动效；触屏设备无指针，不做陀螺仪替代（无等价价值） |
| 拖拽（Drag）物理反馈 | **不设拖拽型核心操作** | 产品主线是「输入 → 扫描 → 结果 → 分享」单线流转，没有任何需要空间重排的对象 |
| 沉浸式 3D 滚动 / 视差滚动 | 滚动**只承担分段揭示**职责，不做装饰性视差 | 大量仓库条目 + 动效视差会显著拖慢滚动性能并干扰扫读 |
| 注册转化率 | **查询成功率 + 分享卡生成率** | 无账号体系、无注册流程 |
| 加载超过 3 秒的 3D 降级 | 拆成 **三类独立降级**：超时 / 限流 / 分页不完整（§6） | 限流**绝不可**表现为「空结果集」 |
| Hero 区 / 产品展示 / 表单模块 | **M1 检索台** / — / **M2 鉴定结果区** | 与 v4.1 §5 页面结构一一对齐 |

# §1 全局交互原则与设计系统

## 1.1 交互目标与优先级

**一句话目标**：让用户在 **30 秒内**完成「输入用户名 → 看到一份有趣但可信的鉴定 → 愿意分享」，全程不感到被要求做任何事。

优先级（冲突时按序裁决）：

| 级别 | 目标 | 判定标准 |
|---|---|---|
| P0 | **可信** | 用户看到的每个数字都能追溯到一次真实读取，且有时间戳；不知道就说不知道 |
| P0 | **不越权** | 全站不产生任何 GitHub 写行为；查询不上榜 |
| P1 | **看得懂** | 无需注册、无需授权、无需离开站点即可得到完整结论 |
| P1 | **有分寸** | 不评判、不排名用户、不催促清理；语气为「陈述事实 + 一点趣味」 |
| P2 | **可玩** | 灵龛视觉、称号、分享卡是体验增益，**不得**成为读取数据的前置条件 |
| P3 | **可分享** | 分享是用户主动动作，永远先预览后生成 |

## 1.5 动效令牌与原则

> **本节的动效令牌表已由 [`dota2-visual-system.md`](./dota2-visual-system.md) §7 取代** —— 时长、缓动曲线与逐模块降级矩阵以该文件为准。本节正文保留为决定的历史记录；其中**四条动效原则与动效能量守恒**仍然有效。

### 令牌表

| Token | 值 | 用途 |
|---|---|---|
| `--motion-duration-instant` | 120ms | 颜色 / 透明度 / 描边反馈 |
| `--motion-duration-fast` | 200ms | hover、focus 环、展开收起、标签切换 |
| `--motion-duration-base` | 320ms | 卡片入场、抽屉滑入、弹窗缩放 |
| `--motion-duration-quick` | 160ms | 内容淡入淡出、列表重排、交叉淡变 |
| `--motion-duration-modal` | 240ms | 抽屉 / 弹窗的弹入与退场 |
| `--motion-duration-slow` | 480ms | 列表级联、灵龛聚拢 |
| `--motion-duration-scan` | 1600ms | 扫描光带单程（可被中断） |
| `--motion-ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 进入类（元素出现） |
| `--motion-ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | 位移类（滑入滑出、视差） |
| `--motion-ease-standard` | `cubic-bezier(0.4, 0, 0.2, 1)` | 通用（颜色、透明度、hover） |
| `--motion-ease-linear` | `linear` | 循环动画（扫描光带、呼吸） |
| `--stagger-step` | 60ms | 级联相邻项延迟 |
| `--stagger-max` | 480ms | 级联累计延迟上限（超出项同时出现） |

### 四条原则

1. **动效是反馈，不是装饰**。每个动画都必须能回答「它在告诉用户什么」。没有信息量的动画一律删除。
2. **不假装更快**（v4.1 §14.3）。动画时长**不得超过**真实请求时长的 1.2 倍；若请求先返回，动画立即结束，不等动画播完。
3. **不阻塞**。任何动画期间用户可继续操作（可输入新用户名、可滚动、可关闭抽屉）。
4. **位移幅度有上限**：单次入场位移 ≤ 12px，缩放 ∈ [0.96, 1.02]，避免大位移动画造成眩晕。

### 动效能量守恒（性能约束）

- 同一时刻**最多 2 个**持续运行的动画（灵龛光点 + 至多 1 个局部加载指示）。
- `transform` 与 `opacity` 为唯一允许的动画属性；**禁止**对 `width`/`height`/`top`/`left`/`box-shadow` 做动画。
- 长列表禁止逐项入场动画（> 20 项时整体淡入，见 §3 M3.5）。

所有交互元素共享同一套状态机。**状态过渡的时长与缓动一律取 §1.5 令牌，不允许组件自定义**；循环 / 持续动画的周期在其所属模块内单列（如 §M1.4、§1.7、§F3.9、§8.6），并同样不得用于状态过渡。

## 1.7 加载、骨架屏与等待反馈

### 何时出现

| 条件 | 表现 |
|---|---|
| 请求 < 300ms | **不显示**任何加载态，直接渲染结果（避免闪烁） |
| 请求 ≥ 300ms | 显示骨架屏 |
| 请求 ≥ 3s | 骨架屏上方追加一行文字：`还在读取中…（已用 3 秒）`，同时保持骨架不变 |
| 请求 ≥ 8s | 超时处理（§6 E02），进入失败态 |
| 骨架已出现但结构未知 | 使用**内容无关**骨架（等高灰块 + 呼吸），不用假数据 |

### 骨架屏规则

1. **形状必须与真实内容一致**：M2 骨架的行高、列宽与真实卡片一致，避免加载完成时布局跳动（CLS ≈ 0）。
2. 骨架不显示任何具体数字（`—`、`•••` 或纯灰块），**绝不显示假数据或 0**。
3. 骨架背景 `--color-surface-card`，高光使用 1200ms 循环的 8% 白色扫过（`linear-gradient` 位移，非 `box-shadow` 动画）。
4. **超过 600ms 的等待必须有百分比以外的进度暗示**：采用「已读取 N 个仓库」的增量计数（可获得的真实计数），不给假进度条。
5. reduced-motion：骨架高光停止，改为静态 6% 亮度呼吸（0.9→1.0 透明度，2400ms 循环）。

### 错误态不占用骨架位置

失败态**替换**骨架区域（同一高度），不使用 Toast 覆盖在骨架上，避免用户以为还在加载。

## 1.8 反馈层级

| 层级 | 载体 | 持续 | 用于 |
|---|---|---|---|
| 即时（< 100ms 感知） | 控件自身状态变化 | — | hover、按下、校验 |
| 短暂（1.5–4s） | Toast，右下角 / 移动端底部居中 | 3000ms 自动消失；hover 或聚焦时暂停消失 | 复制成功、已隐藏、生成失败 |
| 持久（直到状态改变） | 内联条（banner）或区域替换 | 直到用户关闭或条件解除 | 限流提示、结果不完整提示、已隐藏提示 |
| 模态 | 确认对话框 | 直到选择 | 撤销类不可逆操作前确认 |

**Toast 规则**：单例（同一时刻只显示一个，新的顶替旧的）；带 `role="status"`；移动端从底部升入（避免被拇指遮挡）。**Toast 不得承载需要用户决策的信息**（如「登录失败原因」用内联错误，见 §8.4）。

# §2 信息架构与用户旅程

## 2.2 URL 与路由契约

| 路由 | 页面 | 可分享 | 说明 |
|---|---|---|---|
| `/` | 首页 | 是 | 默认落点，M1 |
| `/u/:username` | 某人鉴定 | 是 | 公开链接，**不构成任何上榜行为**；参数需 URL 编码 |
| `/u/:username/repos` | 某人仓库列表 | 是 | 同上；默认排序同 M3 |
| `/r/:owner/:repo` | 仓库详情 | 是 | 独立分享链接，仍由同一 SPA 承载 |
| `/b/:board` | 榜单 | 是 | `board` ∈ `longest-sleep \| embers \| forks` |
| `/how` | 如何入龛 | 是 | F1 |
| `/manage` | 我的管理 | 否 | 需登录；未登录时**不跳转**，直接渲染 `signed-out`（§F2.8）：「登录并认领」+「无法登录？提交下架申请」 |
| `/t/claim` | 下架申请 | 是 | **无需登录**的异议入口（v4.1 §12.3） |
| `/privacy` | 隐私与数据说明 | 是 | 静态内容 |

**路由规则**：

1. 所有非静态路由由 Worker 以 `index.html` 作为 fallback 返回（客户端路由接管）。
2. **未知路由** → 重定向 `/`，并用内联提示条告知「这个地址没有对应的内容，已回到首页」，不静默跳转。
3. **非法参数**（如 `/u/ 空格`）→ 渲染 404 视图，含「回到首页」与「去查一个人」两个动作。
4. 仓库名大小写：GitHub 仓库名大小写不敏感，路由统一转小写存储、显示用 API 返回的原始大小写。

### 分享链接的社交预览（必须实现）

分享链接被粘贴到 IM / 社交平台时，平台会抓取 `og:` 元信息。因此：

- Worker 端为 `/u/:username` 与 `/r/:owner/:repo` **服务端注入** `og:title`、`og:description`、`og:image`、`og:url`。
- `og:image` 指向一张**服务端渲染或预生成**的卡片图；若预生成不可用，至少回退到站点默认图，**不得**返回 404。
- `og:title` 只包含公开事实（例：`@alice 的灵龛鉴定 · 时光收藏家`），**不含**任何暗示失败的措辞。
- 该页面的 `robots` 允许索引（榜单页与鉴定页），`/manage` 禁止索引。

## 2.4 用户旅程泳道

### 主线 A：查查自己（占比最高，30–40 秒完成）

```text
A1  进入 /，首屏渲染，输入框自动聚焦（桌面端，移动端不自动聚焦，避免键盘遮挡）
A2  输入 "alice" → 实时校验通过，输入框描边转幽光色，「鉴定一下」按钮由 disabled → enabled
A3  点击「鉴定一下」或按 Enter
        ↓ 输入框保持可编辑；灵龛光点开始聚拢；M2 骨架屏出现（≥300ms 后）
A4  页面平滑滚动到 M2（`scrollIntoView({behavior:'smooth'})`，容器顶部对齐留 24px）
A5  数据到达 → 骨架替换为内容，元素按 stagger 60ms 级联入场
A6  用户读称号 → hover 称号旁 `?` → 看到依据说明
A7  用户点 [查看我的仓库] → 打开 M3 抽屉（桌面右侧 560px / 移动全屏）
A8  用户在列表中点某仓库 → M4 详情抽屉（**同层替换** M3 抽屉，关闭后回到 M3 列表）
A9  用户点 [生成鉴定卡] → F3 打开 → 选择风格 → 预览 → 确认生成 → 下载 PNG
A10 用户复制结果链接 → Toast「结果链接已复制」→ 用户离开
```

**关键点**：A1→A9 全程**无登录、无授权、无强制任务**。A4 的滚动是唯一一次强制滚动，可被用户随时打断（滚动即取消自动定位）。

### 支线 B：围观榜单

```text
B1  首页点「先看看别人睡了多久」→ /b/longest-sleep
B2  顶部固定声明条：「排名仅来自本站已发现并核实的仓库，不代表整个 GitHub。」
B3  Tab 切换三个榜单；余烬榜内有「按 Star / 按最后推送」排序切换（客户端切换，不重新请求）
B4  点条目 → M4 详情抽屉；点 [分享] → F3 单仓库卡片
B5  用户离开。**浏览榜单不会让用户自己的仓库上榜。**
```

### 支线 C：让仓库入龛

```text
C1  /how → 三步说明 + 主按钮「复制 Topic」
C2  点击 → 剪贴板写入当前配置的主题（默认 `repo-vessel`，§0.5.1）→ Toast「已复制，去 GitHub 给仓库贴上它吧。」
        （剪贴板 API 不可用 → 降级为选中文本 + 「按住 Ctrl/Cmd+C」提示）
C3  用户去 GitHub 手动添加 Topic（本站不代劳、不自动跳转写操作）
C4  用户回到 /how 的「检查收录状态」，粘贴 `owner/repo` 或仓库链接
C5  得到五选一结果：已经入龛 / 已发现 Topic 等待核实 / 没有找到 Topic / 只收录个人公开仓库 / 暂时无法确认
```

### 支线 D：认领与退出（控制权路径）

```text
D1  任意公开仓库详情（M4）底部：「这是你的仓库吗？」→ [登录并认领]
D2  跳转 GitHub 授权（本站仅申请 `read:user` 级别的身份信息，不申请仓库写权限）
D3  回调后校验 4 项：① 当前登录用户是所有者 ② 所有者是个人账户 ③ 仓库当前公开 ④ 仓库已被收录
D4  全部通过 → 进入 /manage，可隐藏 / 恢复
D5  用户点「隐藏此仓库」→ 确认对话框 → 本站立即下架该仓库及本站可控的分享缓存
D6  用户想退出 → 可移除 GitHub Topic（GitHub 侧操作，本站只给说明）或撤销登录
D7  无法登录/无法认领 → /t/claim 下架申请入口（不需要 GitHub 登录）
```

## 2.5 首屏到结果的滚动编排

| 阶段 | 滚动位置 | 动画 |
|---|---|---|
| 首屏静止 | `scrollY = 0`，M1 占满视口 | 灵龛光点常态漂浮（§3 M1.4） |
| 提交瞬间 | 仍在 0 | 输入框内容保留；光点向中心聚拢（480ms `ease-in-out`）；按钮进入 loading |
| 提交后 120ms | 自动滚到 M2 位置 | 容器 top 对齐，偏移 24px；`behavior: 'smooth'`（此时骨架可能尚未出现） |
| 提交后 300ms | 保持 M2 位置 | 若仍未返回则显示骨架（§1.7） |
| 数据到达 | 保持 M2 位置 | 骨架 → 内容替换；标题 320ms `ease-out` 上移 8px 淡入；数据行按 60ms stagger |
| 用户手动滚动 | 跟随用户 | **取消**自动定位，不再抢回视口 |

**打断规则**：滚动事件一旦由用户触发（`wheel` / `touchmove` / 键盘翻页），自动定位立即取消，之后不再自动跳转。

#### 关于 SLOGAN

- **它是什么**：一句品牌语。它借用 Dota 的**机制**意象（阵亡者的灰烬归入灵龛，充能满了可以为下一个
  项目注入生命），不是 Dota 的名字，也不是对任何仓库的评价。
- **放在哪**：铭牌（灵龛鉴定）与站点标题之间。它是**品牌语气**；站点标题是**这一屏要你做的事**。
  两者顺序反了会变成两段抒情夹一段说明。
- **复用**：第二句「充能完毕，随时准备为下一个项目注入生命。」同时是**灵龛充能等级 Ⅳ 阶**的说明文案
  （§M2.5）—— 那正是「灵龛充满、升级成魂之灵龛」的那一刻。SLOGAN 在共享层只存一份。
- **字号是 H2（20px），不是 Display 的 38px。** 视觉系统 §5.2 把 Display 一级**只留给落地页主标题**，
  一屏放两个 38px 会互相抢；SLOGAN 是**品牌语**，本来就该在主标题之下。所以它用 **Display 字族**
  （`.display-cn`：`--font-display` + `--tracking-wide`）配 **H2 字号** —— 字族决定「这是品牌的声音」，
  字号决定「它不跟主标题平起平坐」。
- **不得越界使用**：SLOGAN **不出现在**仓库卡片、榜单条目、分享图或任何报告里 —— 那些位置上的句子
  会被读成对某个仓库或某个人的事实判断，而产品只陈述事实（§5.3 语气规则 1）。
- **不随语种自动翻译**：繁中 / 英 / 日的 SLOGAN 由 i18n 任务产出（§0.3.1）。

### M1.3 交互逻辑与触发器

#### 输入校验（客户端）

| 规则 | 判定 | 反馈 |
|---|---|---|
| 非空 | 去除首尾空格后长度 ≥ 1 | 空 → 按钮保持 disabled，不报错（未开始输入） |
| 长度 | 1–39 字符 | 超长 → 错误「GitHub 用户名最长 39 个字符」 |
| 字符集 | 仅 `a-z A-Z 0-9 -` | 非法字符 → 错误「GitHub 用户名只能包含字母、数字和连字符」 |
| 连字符位置 | 不能以 `-` 开头或结尾 | 错误「用户名不能以连字符开头或结尾」 |
| 连续连字符 | 不允许 `--` | 错误「用户名不能包含连续的连字符」 |
| 粘贴 URL | 匹配 `github.com/:owner` 或 `:owner/:repo` | **自动提取** owner 并填入；不自动提交 |
| 粘贴 org 链接 | 无法从 URL 判断类型 | 不报错，交给服务端核实（§6 E05） |

**校验时机**：`input` 事件，**去抖 120ms**；失焦时立即校验一次；提交时强制校验（绕过去抖）。

**合法示例**：`alice`、`a-b`、`user123`、`a-b-c`

#### 提交

| 触发 | 行为 |
|---|---|
| 点击「鉴定一下」 | 提交 |
| 输入框内按 `Enter` | 提交（表单 `<form>` 原生行为，保证移动端「完成」键同样有效） |
| 粘贴 URL 后回车 | 提取 owner 后提交 |

**提交后输入框保持可用且可编辑**：用户可在结果出来前改写用户名并再次提交（后一次请求作废前一次的结果渲染）。

### M1.4 灵龛容器动效（Canvas 2D）

> 这是**唯一**的 Canvas 动效区，规格如下。

| 属性 | 值 |
|---|---|
| 实现 | 2D Canvas，`requestAnimationFrame` 驱动 |
| 画布尺寸 | CSS 尺寸 × `devicePixelRatio`（上限 2，避免 3x 屏过度绘制） |
| 光点数量 | 6–12（对应界面文案「几颗代表仓库的小光点」） |
| 光点形态 | 抽象几何：圆角方块 / 圆角括号 / 四角星，三者随机分配 |
| 常态漂浮 | 每个光点独立相位，`sin` 上下浮动 ±6px，周期 3.2–5.6s（随机），水平漂移 ≤ 4px |
| 呼吸 | 透明度 `0.45 → 0.85`，周期 2.8s，`linear` |
| 鼠标跟随 | 指针设备 + 未开启 reduced-motion：整组光点朝指针偏移，**最大 ±6px**，`lerp` 系数 0.06/帧 |
| 聚拢（提交时） | 所有光点向中心 60% 半径收拢，480ms `ease-in-out`；亮度 ×1.4 |
| 散开（结果到达） | 480ms `ease-in-out` 回到常态位置，亮度复原 |
| 帧率上限 | 60fps；连续 3s 无交互且无待处理请求 → 降至 30fps |
| 离屏 / 隐藏 | `document.visibilitychange` 隐藏时**完全停止** RAF |
| reduced-motion | **完全静态**：绘制一次固定分布，不启动 RAF；提交/结果状态改用**文字 + 边框**反馈（见 §8.6） |

**性能守卫**：任一帧绘制耗时 > 8ms → 自动降级为静态图；Canvas 上下文创建失败 → 隐藏 Canvas，显示纯 CSS 装饰（页面功能不受影响）。

### M1.5 状态机

| 状态 | 进入条件 | 表现 | 离开条件 |
|---|---|---|---|
| `idle` | 初始 / 上一次查询结束 | 输入框可编辑，按钮 disabled，光点常态漂浮 | 用户输入或提交 |
| `validating` | 输入变化（去抖 120ms 后） | 计算校验结果 | 校验完成 → `idle` 或 `invalid` |
| `invalid` | 校验失败 | 输入框描边转警示色 + 内联错误文案；按钮保持 disabled；**不发请求** | 用户修改输入 |
| `submitting` | 提交 | 按钮 loading、输入框仍可编辑、光点聚拢、请求发出 | 收到响应 |
| `succeeded` | 收到可用结果 | 光点散开；跳转 M2 渲染 | —（M2 接管） |
| `failed` | 请求失败/超时/用户不存在 | 按钮恢复；输入框下方内联错误（§6）；光点散开 | 用户重试或修改输入 |

### M1.6 动效演进

```text
提交
 ├─ 0ms    按钮 → loading（旋转指示器出现，opacity 0→1，120ms ease-standard）
 ├─ 0ms    光点开始聚拢（0→480ms ease-in-out）
 ├─ 120ms  页面启动向 M2 的平滑滚动
 ├─ ≥300ms M2 骨架屏淡入（opacity 0→1，200ms ease-out）
```

```ts
type SubmitState = 'idle' | 'validating' | 'invalid' | 'submitting' | 'succeeded' | 'failed';

const GITHUB_LOGIN = /^[a-zA-Z0-9](?:[a-zA-Z0-9]|-(?=[a-zA-Z0-9])){0,38}$/;

function validate(raw: string): { ok: boolean; username?: string; message?: string } {
  const trimmed = raw.trim();
  if (!trimmed) return { ok: false, message: undefined };            // 空：不报错，视为未开始
  const fromUrl = extractOwnerFromGithubUrl(trimmed);               // 支持 owner/repo 与完整 URL
  const candidate = fromUrl ?? trimmed;
  // 四条错误文案与 §M1.3 输入校验表一一对应，不得合并成一条通用提示
  if (candidate.length > 39)  return { ok: false, message: 'GitHub 用户名最长 39 个字符' };
  if (!/^[a-zA-Z0-9-]+$/.test(candidate))
                           return { ok: false, message: 'GitHub 用户名只能包含字母、数字和连字符' };
  if (candidate.startsWith('-') || candidate.endsWith('-'))
                           return { ok: false, message: '用户名不能以连字符开头或结尾' };
  if (candidate.includes('--')) return { ok: false, message: '用户名不能包含连续的连字符' };
  if (!GITHUB_LOGIN.test(candidate)) {
    return { ok: false, message: '这看起来不像 GitHub 用户名。用户名只能包含字母、数字和连字符，且最长 39 个字符。' };
  }
  return { ok: true, username: candidate };
}

async function onSubmit(e: Event) {
  e.preventDefault();
  if (state === 'submitting') return;                               // 幂等
  const v = validate(input.value);
  if (!v.ok) { if (v.message) showInlineError(v.message); return; }

  clearInlineError();
  state = 'submitting';
  requestSeq++;                                                     // 递增序号，用于丢弃过期响应
  const seq = requestSeq;
  urnCanvas.playGather();                                            // 480ms 聚拢

  const result = await api.inspect(v.username!, { signal: controller.signal });
  if (seq !== requestSeq) return;                                   // 已有更新的请求，丢弃本次结果

  state = result.ok ? 'succeeded' : 'failed';
  urnCanvas.playScatter();
  if (result.ok) {
    renderM2(result.data);                                          // 骨架 → 内容
    scrollToM2();                                                   // 用户滚动可打断
  } else {
    showInlineError(mapErrorToCopy(result.error));                  // §6
  }
}
```

### M2.5 灵龛充能等级

#### 概念

用户公开仓库中**带主题**的那些，就是「住进灵龛的」—— 每一个算一缕灵魂。数量决定等级。
这是从 Dota 的**机制**借来的（影之灵龛收集阵亡英雄的灵魂，充能满了升级成魂之灵龛），
不是它的名字。

| 等级 | 门槛（带主题的公开仓库数） | 标签 | 星标 | 说明文案 |
|---|---|---|---|---|
| 0 | 0 | 未启封 | — | 还没有仓库住进来。给一个公开仓库加上主题，它就会住进来。 |
| Ⅰ | 1 – 4 | Ⅰ 阶 | ★ | 灵龛刚点上火。 |
| Ⅱ | 5 – 9 | Ⅱ 阶 | ★★ | 已经攒下一点灰烬。 |
| Ⅲ | 10 – 24 | Ⅲ 阶 | ★★★ | 灰烬积成了堆。 |
| Ⅳ | 25 + | Ⅳ 阶 | ★★★★ | 充能完毕，随时准备为下一个项目注入生命。 |

#### 硬规则

1. **计数是三态字段。** 字段名 `enrolledCount`（`number | null`）。`null` = 本次读取没能拿到这个数
   → 等级显示 `? 未知`，**不显示充能条**。它**绝不**显示为「未启封」（那是「0」的意思，是一次
   我们没有依据的断言），也**绝不**显示为 `0`。
2. **等级是派生的，不是下发的。** 响应体只带计数；等级由共享层里同一个纯函数算出。前后端不可能
   对等级有分歧，因为它们调用的是同一段代码。
3. **门槛写在共享层的阈值表里**（`src/shared/thresholds.ts`），与「刚刚安静 / 深度待机 / 时间胶囊」
   并排。界面公开的门槛与代码实际用的门槛必须是同一个数。
4. **命名不写金 / 银 / 铜。** 等级标签是**罗马数字 + 阶**，量级由**星标**承担，颜色只是冗余编码：
   数字与星标始终可见，等级**从不**只靠颜色表达。之所以不用金属词，是因为「铜之灵龛」读起来像在
   断言用户是什么材质，而「Ⅲ 阶」读起来是一个阶段。
5. **Ⅳ 阶就是「升级成魂之灵龛」那一刻** —— Dota 里影之灵龛充满后变成魂之灵龛，这里灵龛充满后
   变成可以「注入生命」的容器。
6. **不可购买、不可刷、不可折算积分。** 等级只由公开仓库数决定，没有付费、没有道具、没有连续天数。

#### 充能条

| 情形 | 呈现 |
|---|---|
| 计数未知 | **不显示充能条**（等级显示 `? 未知`） |
| 未启封（0） | 不显示充能条（没有东西可充） |
| Ⅰ / Ⅱ / Ⅲ 阶 | 显示一条**永远朝「稀有」那一端填充**的条，比例 = 本档已装入量 ÷ 本档容量 |
| Ⅳ 阶 | 不显示条，显示「充能完毕」 |

**本档容量**的算法：以该档的**下限**为起点、以下一档的**下限**为终点（不含）的区间。
例：Ⅱ 阶的区间是 `[5, 10)`，容量 5 —— 5 个仓库是 1/5，9 个仓库是 5/5。

**为什么按档算而不是按「距下一档还差多少」算**：后者在刚升档的那一刻恰好是 `0`，会渲染出一条空的条，
违反「计量条永远朝稀有那一端填充，绝不往 0 走」（§7 / 视觉系统 §7.3）。按档算则任何 Ⅰ 阶以上的
档位都不会出现空条，且在档位末尾正好填满。剩余数量由旁边的**文字**承担（「再收 3 个仓库升到 Ⅲ 阶。」），
不靠条来表达。

### M2.7 状态机

| 状态 | 进入条件 | 表现 | 离开条件 |
|---|---|---|---|
| `hidden` | 初始 | M2 不渲染，高度 0 | 收到查询请求 |
| `loading` | 请求发出 ≥ 300ms | 骨架屏（形状同真实布局） | 收到响应 |
| `ready` | 数据完整 `complete` | 完整内容 | — |
| `partial` | 数据完整 `partial` | 内容 + 顶部不完整提示条 | 用户点「重新读取」→ `loading` |
| `stale` | 读取时间超过陈旧阈值（§5.4） | 内容 + 时间戳转弱化样式 + 「这是 X 天前的数据」 | 重新读取 |
| `failed` | 请求失败/超时 | 区域内联错误 + [重试] 按钮；**保留用户输入** | 重试 → `loading` |

**`partial` 与 `failed` 的区别**：`partial` 有可用数据，必须展示；`failed` 无可用数据，**不得**渲染任何数字（尤其不得显示 0）。

```ts
function deriveTitle(data: InspectResult): Title {
  const repos = data.repos;                       // 仅含本次成功读取的仓库
  if (repos.length < 3 || data.completeness === 'partial') {
    return { name: '神秘访客', ruleId: 'visitor', evidence: [] };
  }
  const total = repos.length;
  const forks = repos.filter(r => r.isFork);
  const originals = repos.filter(r => !r.isFork);
  const dormant = repos.filter(r => r.dormantDays >= 181);
  const embers = repos.filter(r => r.dormantDays >= 365 && r.starCount >= STAR_THRESHOLD_EMBERS);

  if (repos.some(r => r.dormantDays >= 1095)) return title('time-collector');
  if (embers.length >= 1)                     return title('ember-keeper');
  if (forks.length / total >= 0.5 && forks.length >= 3) return title('fork-voyager');
  if (originals.length >= 8 && originals.length / total >= 0.7) return title('idea-sower');
  if (dormant.length === 0)                    return title('light-traveler');
  return title('mystery-visitor');              // 理论不可达，兜底
}

  renderRepresentativeCards(pickRepresentatives(result));
```

| 最近更新 | 最后推送时间降序（= 沉睡天数升序） | |

**筛选 Chips**（多选，AND 组合）：

| Chip | 条件 |

### M3.4 状态标签

标签规则来自 v4.1 §8.2，阈值在 §5.5 公开。**解释文案以 §5.3「状态标签文案」表为唯一来源**，两处不得各写一份。

| 标签 | 条件 | 语义色 | 可点击 | 说明文案（点击后） |
|---|---|---|---|---|
| 刚刚安静 | 181 ≤ 沉睡 < 365 天 | `--color-text-secondary` | 是 | 有一段时间没有推送了。这不代表它停止了维护，只说明最后推送时间在这里。 |
| 深度待机 | 365 ≤ 沉睡 < 1095 天 | `--color-glow-primary` | 是 | 按最后推送时间算，这个仓库有一段时间没有变化了。 |
| 时间胶囊 | 沉睡 ≥ 1095 天 | `--color-glow-accent` | 是 | 最后一次推送距今已超过三年。这不代表项目已经失效，它也可能只是被好好收着。 |
| 余烬未熄 | 沉睡 ≥ 365 天 且 Star ≥ 32 | `--color-glow-accent` | 是 | 仓库安静了一段时间，但仍然有人给它点了 Star。Star 数不代表它现在仍在被使用。 |
| 远行的 Fork | `isFork == true` | `--color-glow-secondary` | 是 | 这是一个 Fork，出发自另一个公开项目。 |
| 已归档 | `archived == true` | `--color-text-muted` | 是 | GitHub 上这个仓库已被作者归档。这是你在 GitHub 上的状态，本站没有改动它。 |

**标签规则**：

1. 一个仓库可同时有多个标签（如「时间胶囊」+「余烬未熄」+「已归档」），最多显示 **3 个**，其余折叠为 `+N`，`+N` 可点击展开。
2. 标签按固定顺序排列：**时间胶囊 → 深度待机 → 刚刚安静 → 余烬未熄 → 远行的 Fork → 已归档**（休眠程度优先，Fork 与归档在后）。
3. **所有标签都可点击**查看依据（不是只有带 `?` 的才有）。点击打开解释卡片（非模态 popover），含规则原文与该仓库的具体数值。
4. 标签颜色**不作为唯一区分手段**（色盲友好）：每个标签必须有文字。
5. 标签的 `aria-label` 形如「时间胶囊：最后推送距今 1,024 天。查看依据。」
6. **沉睡天数未知时不给休眠类标签**。`? 未知`（最后推送未知）的仓库不套用刚刚安静 / 深度待机 / 时间胶囊 / 余烬未熄，标签位显示 `? 未知`（§5.2），**不得按 0 天处理**。

### M3.5 列表性能与虚拟滚动

| 条件 | 策略 |
|---|---|
| 仓库数 ≤ 20 | 全部渲染，**逐项入场动画允许**（stagger 取 `--stagger-step` 60ms，累计上限 `--stagger-max` 480ms） |
| 仓库数 > 20 | 全部渲染，**禁止**逐项入场动画，改为整体淡入 `--motion-duration-fast`（200ms） |
| 仓库数 > 60 | 虚拟列表（视口渲染 + 上下各 8 行缓冲）；仍为整体淡入，不逐项入场 |
| 仓库数 > 500 | 虚拟列表 + 筛选结果计数即时显示（不等待渲染完） |

> 逐项入场的 20 项上限与 §1.5 性能约束、§M5.7 榜单条目阈值一致；60 项是**虚拟列表**阈值，不是逐项入场阈值。

虚拟列表必须保留：**筛选后的计数、排序、与 M4 的联动**。

### M3.8 伪代码

```ts
// 沉睡天数越大 = 最后推送越久以前 = 越「沉睡」
// 「最后推送时间升序」= 沉睡天数**降序**（最久没动的在前）
const sorters = {
  'longest-dormant': (a, b) => b.dormantDays - a.dormantDays,
  'recently-pushed': (a, b) => a.dormantDays - b.dormantDays,
  'most-starred':    (a, b) => b.starCount - a.starCount || b.dormantDays - a.dormantDays,
  'name':            (a, b) => `${a.owner}/${a.name}`.toLowerCase().localeCompare(`${b.owner}/${b.name}`.toLowerCase(), 'zh-Hans-CN'),
};

function applyView(repos: Repo[], filters: FilterSet, sorter: keyof typeof sorters): Repo[] {
  return repos
    .filter(r => matchesFilters(r, filters))       // 纯函数，无副作用
    .sort(sorters[sorter]);
}

function matchesFilters(r: Repo, f: FilterSet): boolean {
  if (f.dormantOnly && r.dormantDays < 181) return false;
  if (f.originalOnly && r.isFork) return false;
  if (f.forkOnly && !r.isFork) return false;
  if (f.archivedOnly && !r.archived) return false;
  if (f.embersOnly && !(r.dormantDays >= 365 && r.starCount >= 32)) return false;
  if (f.topicOnly && !r.topics.includes(TOPIC)) return false;
  return true;
}

function deriveTags(r: Repo): Tag[] {
  const tags: Tag[] = [];
  if (r.dormantDays >= 1095) tags.push({ id: 'capsule',   label: '时间胶囊' });
  else if (r.dormantDays >= 365) tags.push({ id: 'standby', label: '深度待机' });
  else if (r.dormantDays >= 181) tags.push({ id: 'quiet',   label: '刚刚安静' });
  if (r.dormantDays >= 365 && r.starCount >= 32) tags.push({ id: 'ember', label: '余烬未熄' });
  if (r.isFork) tags.push({ id: 'fork', label: '远行的 Fork' });
  if (r.archived) tags.push({ id: 'archived', label: '已归档' });
  return tags;                                     // 顺序即 §M3.4 规定顺序
}
```

### M4.3 Fork 来路卡

#### 卡片结构

```text
它从哪里来？

你的 Fork
alice/project
最后推送：892 天前
      ↓ 来自
来源仓库
original/project
状态：可访问
最后推送：45 天前

[打开来源仓库]
```

#### 四种来源状态（v4.1 §10.1）

| 来源状态 | 判定 | 呈现 |
|---|---|---|
| `personal-upstream` | 上游是**个人**账户的公开仓库且可访问 | 完整卡片，显示上游名、最后推送、可访问状态；提供「打开来源仓库」外链 |
| `org-upstream` | 上游属于**组织** | **只显示已知线索**（上游名称或链接，若公开元数据中已有）；下方固定说明：「这个 Fork 来自一个组织仓库。本站不读取组织仓库信息。」不展示其活跃状态、不做提交比较 |
| `unreachable-upstream` | 来源名称**已知**，但上游仓库被删除 / 私有化 / 无法访问（§6 E07） | **保留已知来源名称**，状态标注「暂时无法访问」；上游最后推送位显示 `? 未知`（**不是 0 天**）；不提供「打开来源仓库」外链 |
| `unresolved` | 连来源名称都无法确认（Fork 记录中没有 `parent` / `source` 信息） | 「这段旅程的起点，暂时无法确认。」不显示任何推测 |

#### 明确不做（v4.1 §10.1 / §10.2）

- **不**展示「领先 / 落后提交数」作为第一版内容（需选定分支，成本高且易缺失；v4.1 §9.4 明确列为后续增强）。
- **不**给出「删除」「同步」「上游已修复」等建议。卡片底部只允许一句：「想继续了解？可以前往 GitHub 查看双方仓库。」
- 上游不可达时**不**降级为「未知项目」——原文保留来源名称，状态标注为「暂时无法访问」（`unreachable-upstream`）；**只有连来源名称都拿不到时**才用 `unresolved`。二者不可混用。

### M4.4 状态机

| 状态 | 进入条件 | 表现 | 离开条件 |
|---|---|---|---|
| `closed` | 默认 | 不渲染 | 触发打开 |
| `opening` | 点击仓库行 / 路由进入 `/r/:owner/:repo` | 遮罩淡入 + 抽屉滑入 | 动画结束 |
| `open` | 动画完成 | 可交互，焦点落在标题（`h2`，`tabindex="-1"`） | ESC / 关闭按钮 / 点击遮罩 / 路由离开 |
| `loading-source` | 正在核实上游 | 来路卡位置显示 3 行骨架 | 返回 |
| `open-with-unknown-source` | 上游不可达 | 来路卡显示 `unreachable-upstream` 态（保留来源名称，标「暂时无法访问」）；来源名称也拿不到时显示 `unresolved` 态 | — |

### M4.6 伪代码

```ts
type SourceState =
  | { kind: 'personal'; owner: string; repo: string; lastPushedAt: string | null }
  | { kind: 'org'; owner: string; repo: string; note: '本站不读取组织仓库信息' }
  | { kind: 'unreachable'; owner: string; repo: string }   // 名称已知，上游不可达（§6 E07）
  | { kind: 'unresolved' };                                // 名称也拿不到

function renderSourceCard(s: SourceState) {
  switch (s.kind) {
    case 'personal':
      return {
        upstream: `${s.owner}/${s.repo}`,
        lastPushed: s.lastPushedAt ? formatDays(s.lastPushedAt) : UNKNOWN,   // 未知≠0
        accessibility: '可访问',
        link: `https://github.com/${s.owner}/${s.repo}`,
        footer: '想继续了解？可以前往 GitHub 查看双方仓库。',
      };
    case 'org':
      return {
        upstream: `${s.owner}/${s.repo}`,          // 仅使用公开元数据中已有的线索
        lastPushed: NOT_SHOWN,                     // 组织上游：明确不展示
        accessibility: '组织仓库，本站不读取其信息',
        link: null,
        footer: '这个 Fork 来自一个组织仓库。本站不读取组织仓库信息。',
      };
    case 'unreachable':
      return {
        upstream: `${s.owner}/${s.repo}`,          // 保留已知来源名称
        lastPushed: UNKNOWN,                       // 上游不可达 → 未知，不是 0
        accessibility: '暂时无法访问',
        link: null,                                // 不提供「打开来源仓库」
        footer: '想继续了解？可以前往 GitHub 查看双方仓库。',
      };
    case 'unresolved':
      return { upstream: null, lastPushed: null, accessibility: null,
               footer: '这段旅程的起点，暂时无法确认。' };
  }
}

// 绝不出现以下分支（产品边界 v4.1 §10.2）：
//   - 领先/落后提交数
//   - '上游已修复' / '建议删除' / '建议同步'
```

```text
[查看详情] [分享]
```

**数据说明**：最长沉睡榜条目底部或展开区显示：「最后推送不等于最后提交，也不代表作者本人不活跃。」

### M5.4 排序切换的实现约束

- 排序切换是**纯客户端操作**：三个榜单的数据在进入榜单区时一次性取回（同一份集合的不同切片），切换排序**不产生新的 GitHub 请求**。
- 若两个榜单的取数范围不同（如 Fork 漂流榜需要 `isFork` 字段），则在首次进入榜单区时并行取三份，骨架统一显示，**不分别闪烁**。
- 切换时用 `--motion-duration-quick`（160ms）`ease-standard` 的位移动画（FLIP 技术），条目**不做逐项入场**。

### M5.5 状态机

| 状态 | 进入条件 | 表现 | 离开条件 |
|---|---|---|---|
| `idle` | 初始 | 榜单区未进入视口，**未发起请求** | 区块进入视口（IO 0.2） |
| `loading` | 进入榜单区 | 骨架（8 行） | 三份数据到位 |
| `ready` | 全部成功 | 榜单内容 | 切榜 |
| `partial` | 部分成功 | 成功部分 + 顶部「部分榜单暂时无法更新」 | 下次刷新 |
| `empty` | 成功但集合为空 | 空状态 + 入龛 CTA | 收录后刷新 |
| `stale` | 数据超过陈旧阈值 | 内容 + 顶部「榜单数据为 X 天前」 | 刷新 |
| `failed` | 全部失败 | 内联错误 + [重试] | 重试 |

### M5.6 动效演进

```text
进入榜单区（滚动触发，IntersectionObserver threshold 0.2，见 §M5.7）
 ├─ 0ms      区块 opacity 0→1 + translateY 12→0（320ms ease-out）
 ├─ 120ms    条目行 opacity 0→1，stagger `--stagger-step` 60ms，累计上限 `--stagger-max` 480ms（条目数 > 20 时改为整体淡入，不逐条入场）
 └─ 切换榜单  旧列表 opacity 1→0（120ms），新列表 opacity 0→1（160ms），FLIP 位移 160ms
```

### M5.7 滚动触发（Intersection Observer）

| 观察对象 | threshold | rootMargin | 行为 |
|---|---|---|---|
| 榜单区块 | 0.2 | `0px 0px -10% 0px` | 首次进入视口触发一次加载；离开不卸载 |
| 榜单条目 | 0.1 | `0px` | 逐条入场（仅当条目数 ≤ 20） |
| M2 结果区 | 0.15 | `0px 0px -15% 0px` | 首次进入 → 记录 `viewed`，用于分享率埋点 |
| 灵龛容器 | 0.5 | — | 不可见时暂停 RAF |

**性能规则**：同一 `IntersectionObserver` 实例复用；回调中不做重计算；卸载时 `disconnect()`。

### M5.8 伪代码

```ts
// 沉睡天数越大 = 最后推送越久以前 = 越「沉睡」
// 「最后推送时间升序」= 沉睡天数**降序**（最久没动的在前）
const BOARD_RULES = {
  'longest-sleep': { dormantMin: 181,  sorter: (a, b) => b.dormantDays - a.dormantDays },
  'embers':        { dormantMin: 365,  starMin: 32, sorter: (a, b) => b.starCount - a.starCount },
  'forks':         { requireFork: true, sorter: (a, b) => b.dormantDays - a.dormantDays },
} as const;

// 余烬榜的排序切换：默认 Star 降序，可切「最后推送升序」
const EMBERS_SORTERS = {
  'star':    (a, b) => b.starCount - a.starCount,
  'pushed':  (a, b) => b.dormantDays - a.dormantDays,
} as const;

function buildBoard(kind: keyof typeof BOARD_RULES, repo: Repo): boolean {
  // 五项收录条件已在上游（服务端）保证，这里只做榜单自身的额外条件
  if (!repo.collected) return false;              // 必须是本站已核实的收录仓库
  if (repo.hiddenByOwner) return false;           // 所有者已隐藏 → 不出现
  const r = BOARD_RULES[kind];
  if (r.dormantMin && repo.dormantDays < r.dormantMin) return false;
  if ('starMin' in r && repo.starCount < r.starMin) return false;
  if ('requireFork' in r && !repo.isFork) return false;
  return true;
}

// 榜单位次与名次徽标：仅对仓库排序，绝不对开发者排序（v4.1 §9.5）
function renderBoardRows(rows: Repo[]) {
  return rows.map((r, i) => ({ rank: i + 1, repo: r, badgeTone: i < 3 ? ['gold','violet','teal'][i] : 'muted' }));
}
```

### F2.2 授权范围说明（必须在授权前明示）

授权前页面必须列出并让用户看到：

- 本站需要什么：**确认你是你的 GitHub 身份**（读公开资料 + 公开的仓库元数据）。
- 本站**不**要什么：私有仓库访问、仓库写权限、代码内容、你的组织信息。
- 授权后可以做什么：认领并隐藏/恢复本站展示。
- 授权后**不能**做什么：修改、归档、删除、重命名、同步任何 GitHub 仓库。

授权按钮旁固定一行：**「本站不会修改你的任何 GitHub 仓库。」**

### F2.3 认领校验（四项）

### F2.5 隐藏的完整语义（关键契约）

用户点「隐藏此仓库」并确认后，**以下内容必须同步失效**：

| 对象 | 失效方式 | 时限 |
|---|---|---|
| 榜单条目 | 从三个榜单移除 | **立即** |
| `/r/:owner/:repo` 详情页 | 返回 404 视图：「这个仓库已经不在本站展示了。」 | 立即 |
| `/u/:username` 鉴定结果 | 该仓库从列表与四项数据统计中移除（统计随列表移除而重算） | 立即 |
| 本站生成的分享卡片图片 | 缓存失效，访问时重新生成或返回 404 | ≤ 5 分钟 |
| 分享链接的社交预览 `og:image` | 同上 | ≤ 5 分钟 |
| 认领记录 | 保留（用于恢复），但不再对外展示 | — |

**不承诺的事**（必须在 F2 与 `/privacy` 中说明）：GitHub 搜索索引、第三方平台已缓存的截图、用户自己下载到本地的图片，**无法远程撤回**。

**伪代码**：

```ts
async function hideRepo(repoId: string) {
  const confirmed = await confirmDialog({
    title: '隐藏这个仓库？',
    body: '它会立刻从本站的榜单和分享页面中消失。GitHub 上的仓库不会有任何变化。',
    confirmText: '隐藏',
    cancelText: '再想想',
    danger: false,                                   // 非危险操作：只是本站不再展示
  });
  if (!confirmed) return;

  await api.setHidden(repoId, true);                 // 服务端置 hidden
  invalidateSiteCaches(repoId);                     // §F2.5 全部对象
  toast('已从本站隐藏。GitHub 上的仓库没有变化。');
}

function invalidateSiteCaches(repoId: string) {
  bustCache(`/api/repo/${repoId}`);
  bustCache(`/api/share-card/${repoId}`);
  bustCache(`/api/u/*`);                            // 统计含该仓库的鉴定结果
  revalidate(`/og-image/r/*/${repoId}`);             // 社交预览
  purgeEdgeCache([`/b/longest-sleep`, `/b/embers`, `/b/forks`]);
}
```

### F2.8 状态机

| 状态 | 进入条件 | 表现 |
|---|---|---|
| `signed-out` | 未登录 | 「登录并认领」按钮 + 「无法登录？提交下架申请」链接 |
| `authorizing` | 点击登录 | 跳转 GitHub（离开本站） |
| `authorizing-error` | 授权失败/被拒 | 内联错误 + 重试 + 改走下架申请 |
| `verifying` | 回调成功 | 「正在确认仓库归属…」骨架 |
| `claimed` | 四项校验通过 | 进入 `/manage` |
| `claim-failed` | 任一校验失败 | 对应失败文案（§F2.3）+ 下架申请入口 |
| `signed-in` | 已有有效会话 | 直接进入 `/manage` |
| `signed-in-empty` | 已登录且会话有效，但名下**没有**已认领仓库 | `/manage` 空状态：「你还没有认领任何仓库」+「去查一个人」+「如何入龛」入口；**不**显示成错误。认领第一个仓库后回到 `signed-in` |

### F3.2 三步流程

```text
Step 1  选择内容        Step 2  选择风格        Step 3  预览 → 确认生成

                                                │  - 称号 时光收藏家│
                                                │  - 最长沉睡 1024天│

```

- Step 1 与 Step 2 在同一弹层内左/右分栏；Step 3 是**独立的确认视图**（必须显式点击「确认并生成」才出图）。
- 选择「某个仓库 / 某条榜单条目」时，Step 1 顶部显示来源上下文（`来自榜单 · 最长沉睡榜 #01`），避免用户混淆分享对象。

### F3.3 卡片内容规范

| 卡片类型 | 必含字段 | 禁止字段 |
|---|---|---|
| 鉴定卡 | 用户名、称号、最长沉睡天数、公开 Fork 数、数据读取时间、一句称号文案、站点标识 | 私有仓库信息、未读取到的字段、任何失败/失败率/工时估算 |
| 仓库卡 | `owner/repo`、状态标签 + 对应数值、最后推送日期、一句氛围文案 | 对仓库状态的评价（失败/废弃）、上游活动推断 |
| 榜单条目卡 | 名次、榜单名、`owner/repo`、沉睡天数、Star/Fork | 对开发者的任何排名或评价 |

**氛围文案**（可轮换，固定文案库，不生成新句子）：
- 仓库卡：「最后一次推送，还停在那个春天。」
- 鉴定卡：使用称号对应文案（§M2.4）。

**禁止**：任何由数据「推断」出的句子（如「这个项目失败了」）。文案只允许**基于日期与星数的氛围化描述**，且必须与数据无因果关系。

### F3.4 图片规格

| 项 | 值 |
|---|---|
| 比例 | 1200×630（横版，分享链接预览友好）+ 1080×1080（方形，社交平台友好），用户切换 |
| 格式 | PNG（主）+ WebP（可选，减小体积） |
| 背景 | 纯色或极简渐变，**不得**引入渲染差异大的复杂纹理 |
| 最小字号 | 24px（1200px 宽画布下），保证在移动端缩略图中可读 |
| 品牌标识 | 右下角固定，含站点名，**不可被裁切** |
| 数据时间戳 | 必含，格式「数据读取于 2026-10-30」 |

### F3.5 「将公开」清单（强制）

生成前必须展示一份**可勾选的公开清单**：

- 默认为**全选**（用户不需要逐项操作就能完成流程）。
- 每一项前带复选框，可取消勾选；取消某项后，卡片对应位置显示 `—` 或整块不渲染，**不留空槽**。
- 清单内容随分享类型变化：

| 类型 | 清单项 |
|---|---|
| 鉴定卡（查自己） | 用户名 · 称号 · 最长沉睡天数 · 公开 Fork 数 · 已归档数 · 读取时间 |
| 鉴定卡（查他人） | **用户名单独列出**，并置顶提示：「这张卡片会包含 @alice 的公开信息。」 |
| 仓库卡 | 仓库名 · 状态标签 · 最后推送日期 · Star 数 · 读取时间 |
| 榜单条目卡 | 榜单名 · 名次 · 仓库名 · 沉睡天数 · Star 数 · 读取时间 |

**禁止**：任何未在清单中列出的字段出现在卡片上。服务端生成时以清单为白名单校验。

### F3.6 分享链接

| 项 | 规则 |
|---|---|
| 形态 | `https://<domain>/u/:username?share=1`（鉴定）、`/r/:owner/:repo?share=1`（仓库） |
| 查询他人时 | 链接访问无需登录即可看到**已公开的同一批字段**，且页面顶部同样显示「你正在查看 @alice 的公开灵龛」提示 |
| 副作用 | 打开分享链接**不**产生任何数据写入、不触发收录、不影响榜单 |
| 复制反馈 | Toast「链接已复制」 |

### F3.7 状态机

| 状态 | 进入条件 | 表现 | 离开条件 |
|---|---|---|---|
| `selecting` | 从 M2/M3/M5 唤起 | Step 1 + Step 2 | 选定内容与风格 |
| `previewing` | 选定内容 | Step 3 预览（卡片实时渲染） | 生成 / 关闭 |
| `generating` | 点击「确认并生成」 | 按钮 loading + 预览区显示「正在生成…」遮罩（**不改变卡片位置**） | 完成 / 失败 |
| `generated` | 生成成功 | 展示图片预览 + [下载图片] [复制链接] [重新生成] | 关闭 |
| `failed` | 生成失败 | 预览区错误 + [重试] + **降级方案** | 重试 |
| `source-gone` | 所选仓库在本次打开期间已不可用（被隐藏 / 私有化 / 转入组织 / 删除） | 预览区显示「这个仓库已经不在本站展示了。」+ [换一个内容]；**不显示任何数字**，不把它当成 0 | 换一个内容 → `previewing` |
| `closed` | 关闭 | 焦点还原到唤起按钮 | 再次唤起 |

### F3.8 失败降级（关键）

生成失败（渲染服务超时、字体加载失败、服务端 5xx）时：

1. 保留预览区**结构**，不折叠，不清空已选内容。
2. 错误文案：「图片暂时生成不出来。结果数据还在，你可以直接复制链接分享。」+ [重试]
3. 提供降级出口：**复制链接**（始终可用）与**复制纯文本卡片**（把卡片内容以纯文本复制到剪贴板）。
4. 不弹出模态错误，不清空用户已做的选择。

# §5 数据表达规范

## 5.1 字段三态模型

每个可展示字段有且仅有三种状态，**三者在视觉上必须一眼可分**。

| 状态 | 含义 | 视觉 | 可访问性 |
|---|---|---|---|
| **有值** | 本次读取成功并有数值 | 正常文字 / `--color-data-emphasis` | 直接朗读数值 |
| **未知** | 本次**未能获得**（限流、超时、字段不存在、上游不可达、达到分页上限） | `--color-state-unknown` + 1px 虚线下划线 + 尾部 `?` 图标 | 朗读「未知」+ 原因（`aria-describedby`） |
| **不适用** | 该字段对当前对象无意义 | 同「未知」的视觉，但文案为「不适用」 | 朗读「不适用」 |

**关键区分**：

- **未知 ≠ 0**。`0 个仓库` 是有值；`? 未知` 是未知。二者绝不可互换。
- **未知 ≠ 不适用**。非 Fork 仓库的「上游」是**不适用**；Fork 仓库但上游不可达是**未知**。文案必须不同。
- **未知不得被省略**。数值位不可用时显示占位符，**不隐藏整格**（隐藏会导致用户误以为该维度没有数据）。

### 未知态的通用交互

`?` 图标可聚焦（`tabindex="0"`），聚焦或点击时展示原因说明：

| 原因 | 说明文案 |
|---|---|
| `rate-limited` | GitHub 暂时限制了请求频率，这一项这次没有读到。 |
| `timeout` | 读取超时，这一项这次没有读到。 |
| `not-provided` | GitHub 没有提供这项数据。 |
| `unreachable` | 相关仓库暂时无法访问。 |
| `truncated` | 仓库数量超过本站单次读取上限，这一项只统计了前一部分。 |

## 5.2 逐字段三态定义

| 字段 | 口径 | 有值 | 未知 | 不适用 |
|---|---|---|---|---|
| 仓库名称 | GitHub `name` | `old-project` | `? 未知`（仓库记录未读取到） | — |
| 描述 | GitHub `description` | 原文 | `? 未知`（GitHub 未提供） | — |
| 主要语言 | GitHub `language` | `TypeScript` | `? 未知` | — |
| Star 数 | `stargazers_count` | `128` | `? 未知` | — |
| Fork 数 | `forks_count` | `12` | `? 未知` | — |
| 最后推送时间 | `pushed_at` | `2023-07-14`（+ 相对天数） | `? 未知` | — |
| 创建时间 | `created_at` | `2019-02-01` | `? 未知` | — |
| 是否 Fork | `fork` 布尔 | `原创` / `Fork` | `? 未知`（字段未随本次读取返回） | — |
| 是否归档 | `archived` 布尔 | `已归档` / `未归档` | `? 未知`（字段未随本次读取返回） | — |
| Topic 列表 | `topics` | 当前配置的主题（默认 `repo-vessel`） | `? 未知`（GitHub 未提供） | — |
| **沉睡天数** | `now − pushed_at` | `1,024 天` | `? 未知`（最后推送未知） | — |
| 公开仓库总数 | 本次成功读取数 | `36` | `? 未知`（读取失败） | — |
| 最长沉睡 | `max(沉睡天数)` | `1,024 天` | `? 未知`（无有效仓库） | — |
| 仍有余烬 | 满足条件的仓库数 | `3 个` | `? 未知` | — |
| 公开 Fork 数 | `isFork` 计数 | `12 个` | `? 未知` | — |
| 已归档数 | `archived` 计数 | `4 个` | `? 未知` | — |
| **带主题的公开仓库数** | `enrolledCount`：本人公开仓库中带当前配置主题的计数 | `12 个` | `? 未知`（本次读不到这个数） | — |
| **灵龛充能等级** | 由上一行**派生**（§M2.5） | `Ⅲ 阶` | `? 未知` | — |
| **Fork 来源** | `parent` / `source` | `original/project` | `? 未知`（暂时无法确认） | `不适用`（非 Fork） |
| 上游状态 | 上游仓库可访问性 | `可访问` | `? 未知` | `不适用`（非 Fork / 组织上游不展示） |
| 上游最后推送 | 上游 `pushed_at` | `45 天前` | `? 未知` | `不适用`（组织上游不读取） |
| 读取时间 | 本次查询完成时刻 | `2026-10-30 15:42` | `? 未知`（本次无成功读取） | — |

> 表中的「—」表示**该字段不存在「不适用」态**（例如每个仓库都有沉睡天数）。「不适用」态**实际呈现时**用 `?` 视觉 + 文案「不适用」，不是破折号（§5.1）。

### 必需字段的逐字段视觉对照

「未知」与「不适用」不是全局样式，而是**逐字段**决定的；下表把 §5.1 的三态落到本产品必须呈现的 6 个字段上。`—` 表示该状态对该字段不成立。

| 字段 | 有值 | 未知 | 不适用 | 陈旧（读取时间 > 24h，§5.4） |
|---|---|---|---|---|
| 沉睡天数 | `--color-data-emphasis`，带「天」单位 | `--color-state-unknown` + 虚线下划线 + `?`（原因 `not-provided` / `timeout`） | — | 数值保留，区块顶部追加「这是 X 天前的数据」+ [重新读取] |
| 公开仓库总数 | `--color-data-emphasis` + 「个」 | 同上 + 原因 `rate-limited` / `timeout` / `truncated` | — | 同上 |
| Star 数 | `--color-data-secondary` | 同上 | — | 同上 |
| Fork 数 | `--color-data-secondary` | 同上 | — | 同上 |
| Fork 来源 | `--color-text-primary` + 等宽 `owner/repo` | 同上 + 原因 `unreachable` / `not-provided` | `--color-state-unknown` + 虚线，**文案为「不适用」**（非 Fork） | 值保留，同上提示条 |
| 读取时间 | `--color-text-secondary` + `YYYY-MM-DD HH:mm`（同屏给相对时间） | 同上 | — | 时间戳降为 `--color-text-muted`，并追加「这是 X 天前的数据」+ [重新读取] |

**纪律**：任何一格**不得**因为「读不到」而渲染成 `0`、`—` 或空白；也**不得**整格隐藏（§5.1）。

## 5.3 文案口径

### 可说 / 不可说（对齐 v4.1 §3.1）

| ✅ 可以这样说 | ❌ 不可这样说 |
|---|---|
| 已进入深度待机 | 项目已经失败 |
| 最后一次推送在 892 天前 | 作者遗弃了它 |
| 你的 Fork 和上游暂时走散了 | 你的 Fork 没用了 |
| 这颗星星还亮着 | 你错过了成为明星项目的机会 |
| 适合再看一眼 | 你应该清理它 |
| 暂时没有找到这一类仓库 | 你的仓库毫无价值 |
| 这个仓库安静了 1,024 天 | 你的代码在腐烂 |

### 语气规则

1. **陈述事实 + 一点趣味**。趣味只来自**措辞**，不来自**判断**。
2. **主语是仓库，不是人**。「它已经很久没有变化」，不写「你很久没管它」。
3. **不使用第二人称施压**。可以说「你的公开仓库」，不写「你该动手了」。
4. **禁止词表**（出现即视为不合格）：失败、废弃、浪费、腐烂、垃圾、废物、懒惰、最懒、罪、墓地、坟、尸。本条约束的是**描述仓库或开发者的文案**；描述站点自身技术状态的用词（如「请求失败」「读取超时」「生成失败」）不属于本条范围，但也不得改写成评价仓库或开发者的说法。
5. **数字必须有单位与上下文**：`1,024 天`，不是 `1024`；`3 个仓库`，不是 `3`。
6. **不承诺用户之外的事**：不说「我们会帮你清理」，不说「随时可以删除」。

### 状态标签文案（最终版，v4.1 §8.2 + 本文补充）

| 标签 | 显示文案 | 解释文案（点击后） |
|---|---|---|
| 刚刚安静 | 刚刚安静 | 有一段时间没有推送了。这不代表它停止了维护，只说明最后推送时间在这里。 |
| 深度待机 | 深度待机 | 按最后推送时间算，这个仓库有一段时间没有变化了。 |
| 时间胶囊 | 时间胶囊 | 最后一次推送距今已超过三年。这不代表项目已经失效，它也可能只是被好好收着。 |
| 余烬未熄 | 余烬未熄 | 仓库安静了一段时间，但仍然有人给它点了 Star。Star 数不代表它现在仍在被使用。 |
| 远行的 Fork | 远行的 Fork | 这是一个 Fork，出发自另一个公开项目。 |
| 已归档 | 已归档 | GitHub 上这个仓库已被作者归档。这是你在 GitHub 上的状态，本站没有改动它。 |

## 5.4 时间戳与陈旧度

### 时间戳规格

| 项 | 规则 |
|---|---|

# §6 异常流程与边界条件

## 6.1 异常总表

> **全局纪律**：任何异常都**不得**降级为「空结果」或「0」。错误必须可见、可理解、可恢复。
> 每条异常都必须在服务端标记**完整性**（`complete` / `partial` / `failed`），并向下游传播（§6.2）。

| ID | 场景 | 触发条件 | 系统表现 | 用户可见文案 | 完整性 | 恢复路径 | 阻断? |
|---|---|---|---|---|---|---|---|
| **E01** | GitHub 限流 | GitHub API 返回 `403` 且 `X-RateLimit-Remaining: 0` 或 `429` | 停止后续请求；缓存已有结果 | 「GitHub 暂时限制了请求频率。等一会儿再试。」+ 显示重试倒计时（按 `X-RateLimit-Reset`） | `failed` | 倒计时结束自动重试 / 手动重试 | 是 |
| **E02** | 请求超时 | 单次请求 > 8s（硬超时），或 > 3s（软超时，触发提示文案） | 中止请求；保留已解析的部分 | 软：「还在读取中…（已用 3 秒）」<br>硬：「这次读取超时了。」+ [重试] | `partial`（有部分数据）/ `failed`（无） | [重试] | 否（有部分数据时不阻断） |
| **E03** | 分页不完整 | 第 N 页请求失败，但前 N−1 页成功 | 用已有页渲染结果 | 「本次结果可能不完整：只读取到了前 36 个仓库。」+ [重新读取] | `partial` | [重新读取] | 否 |
| **E04** | 用户不存在 | GitHub 返回 `404` | 不渲染任何数字 | 「没有找到这个用户名。」+ 「检查一下拼写？」+ [换一个用户名] | `failed` | 修改输入 | 是（该次查询） |
| **E05** | 组织账户 | 用户 `type == "Organization"` | **立即停止**，不发起仓库列表请求 | 「这是一个组织账户，本站只查看个人账户的公开仓库。」+ [看看榜单] | `failed` | — | 是 |
| **E06** | 仓库私有化 / 转入组织 | 收录后仓库变私有，或 owner 变为组织 | 下架该条目；分享缓存失效 | 详情页：「这个仓库已经不在本站展示了。」<br>榜单：直接移除 | `complete`（对剩余条目） | 自动 | 否 |
| **E07** | 上游仓库不可达 | Fork 来源仓库被删除 / 私有化 / 无法访问 | 来路卡切 `unreachable-upstream` 态（保留来源名称，状态标「暂时无法访问」）；来源名称也拿不到时切 `unresolved` 态 | 「暂时无法访问」（来源名称仍显示）<br>名称未知时：「这段旅程的起点，暂时无法确认。」 | `complete` | 自动 | 否 |
| **E08** | Topic 缺失 | 收录仓库的 Topic 被移除 | 下架该条目 | 详情页：「这个仓库已经不在本站展示了。」 | `complete` | 自动（下次核实生效） | 否 |
| **E09** | 分享图生成失败 | 渲染服务超时 / 字体加载失败 / 5xx | 预览区结构不变，显示错误 + 降级出口 | 「图片暂时生成不出来。结果数据还在，你可以直接复制链接分享。」+ [重试] + [复制纯文本卡片] | 不影响结果 | [重试] / 复制链接 | 否 |
| **E10** | GitHub 登录失败 | 授权被拒 / 回调参数缺失 / token 失效 | 保留当前位置，不清空任何本地状态 | 「没有完成登录。」+ [重试] + 「无法登录？提交下架申请」 | 不影响结果 | 重试 / 下架申请 | 否 |
| **E11** | 仓库超过读取上限 | 用户公开仓库数 > 1000（本站设定的单次读取上限） | 停止翻页，标记截断 | 「这次最多读取了 1,000 个仓库，你的公开仓库可能更多。」+ 计数显示为「≥ 1,000」 | `partial` | 无法恢复（提示用户） | 否 |
| **E12** | 字段缺失 | 仓库无描述 / 无语言 | 单字段走未知态 | 描述位显示 `? 未知`（GitHub 没有提供这项数据） | `complete` | 无 | 否 |
| **E13** | 认领校验失败 | 四项校验任一不通过 | 不进入 `/manage` | 对应文案（§F2.3）+ 下架申请入口 | 不影响结果 | 改走下架申请 | 否 |

| **E15** | 离线 | `navigator.onLine === false` | 禁止发起新请求 | 「看起来你现在没有联网。连上网络后再试。」 | `failed` | 网络恢复后自动提示重试 | 是（该次操作） |
| **E16** | Canvas 不可用 | 上下文创建失败 / 显存不足 | 隐藏 Canvas，改用 CSS 静态装饰 | 无文案（纯装饰降级，不打扰用户） | `complete` | 无 | 否 |
| **E17** | 剪贴板不可用 | 非安全上下文 / 权限拒绝 | 选中文本 + 手动复制提示 | 「无法自动复制，请按住 Ctrl / Cmd + C 复制。」 | 不影响结果 | 手动复制 | 否 |
| **E18** | 榜单数据为空 | 收录集合为空（正常情况） | 空状态 | 「还没有仓库住进来。」+ 「想让你的仓库被发现？给公开仓库加上 `repo-vessel` Topic。」（主题名为配置值）+ [去入龛] | `complete` | — | 否 |

### 6.1.1 三类降级的严格区分（不可混用）

| 情况 | 判定 | 绝不可表现为 |
|---|---|---|
| **限流**（E01） | 请求被拒绝，未获得数据 | 空列表 / 「0 个仓库」 |
| **部分成功**（E03/E11） | 拿到部分数据 | 「完整结果」/ 省略提示条 |
| **确实没有**（E18） | 请求成功且集合为空 | 任何错误样式（不应用琥珀色） |

「确实没有」用**中性空状态**（无警示色）；「无法确认」用**未知态**或警示条——两者的视觉必须不同。

## 6.2 完整性标记传播规则

```
partial / failed 标记必须沿链路传播，禁止在中间层被丢弃或被折算为 0：

GitHub API 响应
   └─> 分页聚合层      合并各页结果，记录 missingPages[]
         └─> 领域层    标记 completeness = complete | partial | failed
               └─> 缓存层   partial 结果可缓存，但必须连同 completeness 一起缓存
                     └─> API 响应体   { data, completeness, missingPages[], readAt }
                           └─> UI 层   completeness 驱动全局提示条与统计三态
```

**规则**：

1. `completeness` 是响应体的**一等字段**，不是 HTTP 状态码的替代品。`200 + partial` 是合法响应。
2. UI **不得**根据「数组为空」自行推断 `complete`；必须读 `completeness`。
3. `failed` 时，响应体中**不含**任何统计数字（不返回 `repoCount: 0`，返回 `repoCount: null`）。
4. 缓存中的 `partial` 数据在 TTL 到期前复用时，仍需重新展示提示条。

## 6.3 性能与资源边界

| 项 | 值 | 超限行为 |
|---|---|---|
| 首屏关键资源（JS + CSS + 字体） | ≤ 200KB gzip | 超出则拆分路由级代码分割 |
| LCP（首屏输入框可见） | ≤ 1.8s（4G 慢速） | 优先保证输入框与文字优先渲染 |
| INP | ≤ 200ms | 长任务拆分，`requestIdleCallback` 处理非关键计算 |
| CLS | ≤ 0.1 | 骨架屏尺寸与真实内容一致（§1.7） |
| 单次请求超时 | 8s 硬 / 3s 软 | 见 E02 |
| 仓库读取上限 | 1000 个 | 见 E11 |
| 分享图生成超时 | 10s | 见 E09 |
| Canvas 帧预算 | ≤ 8ms/帧 | 超限降级为静态（§M1.4） |
| 持续动画数量 | ≤ 2 | 超出时暂停次要动画 |
| 字体 | 中文正文 2 个字重（400/600），`font-display: swap` | 不阻塞首屏 |

| 仓库数 | 策略 |
|---|---|
| ≤ 20 | 全量渲染 + 级联入场（stagger 60ms，累计上限 480ms） |
| 21 – 60 | 全量渲染 + 整体淡入（200ms），不逐项入场 |

- 所有装饰性图形使用 SVG 或 CSS，无位图大图。
- 分享卡渲染使用**服务端字体子集**，字体加载失败时使用回退字体并接受轻微排版差异（**不得**因此整体失败）。

# §8 无障碍（WCAG 2.1 AA）

**目标等级**：WCAG 2.1 **AA**。下表对比度已按 WCAG 相对亮度公式核算。

## 8.1 语义结构与地标

| 区域 | 语义 | 要求 |
|---|---|---|
| 页面外壳 | `<header>` / `<main>` / `<footer>` | 各页仅一个 `<main>`；`<h1>` 每页唯一 |
| 顶部导航 | `<nav aria-label="主导航">` | 内部链接使用 `aria-current="page"` 标记当前项 |
| 搜索区（M1） | `<form role="search">` | 输入框 `<label>` 显式关联（视觉隐藏但存在） |
| 结果区（M2） | `<section aria-labelledby="m2-title">` | 标题 `h1`，区块标题 `h2` |
| 抽屉 | `role="dialog" aria-modal="true"` | `aria-labelledby` 指向标题 |
| 榜单 Tab | `role="tablist"` / `role="tab"` / `role="tabpanel"` | 需键盘方向键切换（§8.7） |
| 标签解释 | `role="dialog"`（非模态）+ `aria-modal="false"` | 焦点进入，关闭后焦点还原到标签 |
| 骨架屏 | `aria-busy="true"` | 加载时对屏幕阅读器隐藏占位内容 |
| 实时区 | `role="status"`（礼貌播报） | 复制成功、生成成功等 |
| 错误区 | `role="alert"`（断言播报） | 输入校验错误、请求失败 |

**标题层级**：不得跳级（`h1` → `h2` → `h3`）。抽屉内的标题为 `h2`（配 `tabindex="-1"`）。

## 8.3 焦点管理

| 场景 | 行为 |
|---|---|
| 路由切换（SPA） | 焦点移到新页面的 `<h1>`（`tabindex="-1"`），并通过 `aria-live` 播报页面标题 |
| 抽屉打开 | 焦点移到抽屉标题；`body` 滚动锁定；背景内容 `inert` |
| 抽屉关闭 | 焦点还原到触发元素；若触发元素已不存在（如路由跳转），移到当前页 `<h1>` |
| 模态确认框 | 同抽屉规则，焦点移到对话框标题 |
| 标签解释弹出 | 焦点移到解释卡首个可聚焦元素；`Esc` 关闭并还原到标签 |
| Toast 出现 | **不抢焦点**；`role="status"` 礼貌播报 |
| 表单提交失败 | 焦点移到错误摘要（`role="alert"` 容器） |
| 骨架 → 内容替换 | 焦点**不移动**，但内容容器更新为 `aria-busy="false"` |
| 复制链接成功 | 不移动焦点 |

## 8.4 ARIA 契约

### 关键属性

| 元素 | 属性 |
|---|---|
| 用户名输入框 | `type="text"` `autocomplete="off"` `spellcheck="false"` `aria-describedby="search-hint search-error"` `aria-invalid`（仅校验失败时） |
| 提交按钮 | `type="submit"`；loading 时 `aria-busy="true"`，文案保持「鉴定一下」不改为空 |
| 加载容器 | `aria-busy="true"` + `aria-label="正在读取仓库"` |
| 抽屉 | `role="dialog"` `aria-modal="true"` `aria-labelledby="drawer-title"` |
| 标签按钮 | `aria-haspopup="dialog"` `aria-expanded="false"` `aria-label="时间胶囊：最后推送距今 1,024 天。查看依据。"` |
| 未知态 `?` | 原因必须随字段一起读出：`aria-label="未知：GitHub 暂时限制了请求频率"`。**实现上是纯文本标记 + 视觉隐藏的原因文本，不是一个按钮** —— `?` 出现在整张卡就是 `<button>` 的仓库卡上，按钮里不能再套按钮（嵌套可交互元素是无效 HTML，读屏也会跳过它） |
| 排序切换 | `role="group" aria-label="排序方式"`，选中项 `aria-pressed="true"` |
| 榜单 Tab | `role="tablist"`，`aria-selected`，`aria-controls` 指向 panel |
| 数据格 | `<div role="group" aria-label="最长沉睡，1,024 天">` |
| 分享生成器 | `role="dialog" aria-modal="true"`，内部 Step 用 `aria-current="step"` |
| 复制结果 | `aria-live="polite"` 容器承载「链接已复制」 |

### 播报文本（结果到达时）

```
role="status" 内容：
"@alice 的灵龛鉴定已读取完成。本次读取到 36 个个人公开仓库。称号：时光收藏家。最长沉睡 1,024 天。结果中有 3 处数据未知。"
```

**必须包含**：读取数量、称号、未知项数量。**不得**包含：判断性措辞。

### 语义化标签与 `lang`

- `<html lang="zh-CN">`。
- 仓库名、代码片段用 `<code>` 或 `font-family: mono` + `lang="en"`（用户名是 ASCII）。
- 英文专有名词（Star、Fork、Topic）保留原文，**不翻译**。

## 8.5 对比度

> **本表已由 [`dota2-visual-system.md`](./dota2-visual-system.md) §3.3 取代** —— 新令牌集的实测对比度覆盖五个底色，以该文件为准（表中 token 名为旧令牌名）。本表保留为决定的历史记录；表下的**五条规则**仍然有效。

以下为按 WCAG 2.1 相对亮度公式实测值（三种实际背景：页面底 `#0B0F14`、卡片面 `#151C26`、浮层面 `#1A222E`）。**改动任一 hex 必须重算本表**。

| 前景 | vs `#0B0F14` | vs `#151C26`（卡片） | vs `#1A222E`（浮层） | 结论 |
|---|---|---|---|---|
| `--color-text-primary` `#EDE6DA` | **15.5 : 1** | 13.8 : 1 | 12.9 : 1 | ✅ AAA |
| `--color-text-secondary` `#A8B2BF` | **9.0 : 1** | 8.0 : 1 | 7.5 : 1 | ✅ AAA |
| `--color-text-muted` `#818D9C` | **5.7 : 1** | 5.1 : 1 | 4.7 : 1 | ✅ AA（三种背景全部达标，字号不限） |
| `--color-glow-primary` `#45C9B8` | **9.4 : 1** | 8.4 : 1 | 7.9 : 1 | ✅ AAA |
| `--color-glow-secondary` `#B79BE8` | **8.1 : 1** | 7.2 : 1 | 6.8 : 1 | ✅ AAA |
| `--color-glow-accent` `#C9A24B` | **8.0 : 1** | 7.1 : 1 | 6.7 : 1 | ✅ AAA |
| `--color-data-emphasis` `#CFF3EE` | **16.2 : 1** | 14.4 : 1 | 13.5 : 1 | ✅ AAA |
| `--color-data-secondary` `#8FA3B5` | **7.4 : 1** | 6.6 : 1 | 6.2 : 1 | ✅ AAA |
| `--color-state-unknown` `#7E8A99` | **5.5 : 1** | 4.9 : 1 | 4.6 : 1 | ✅ AA |
| `--color-alert-warn` `#E0A340` | **8.7 : 1** | 7.7 : 1 | 7.2 : 1 | ✅ AAA |
| `--color-alert-stop` `#E06C5B` | **5.9 : 1** | 5.3 : 1 | 4.9 : 1 | ✅ AA（对比度达标；**用法**受规则 3 限制） |

**规则**：

1. 正文与小字（< 18.66px）对比度 **≥ 4.5:1**；大字与图形 **≥ 3:1**。上表所有颜色在三种背景上均满足小字 AA。
2. `--color-text-muted` 在浮层（抽屉）上仍仅用于**非关键信息**（时间戳、辅助标注）；关键信息不得使用。这是**层级约束**，不是对比度约束。
3. `--color-alert-stop`（红）**只用于硬错误**，且不得用于文字段落，仅用于图标、描边与短标签。
4. **焦点环** `--color-glow-primary` 与相邻背景对比度 ≥ 3:1（9.4:1，满足）。
5. 禁用态（`opacity .45`）不参与对比度要求，但**不得**用于唯一传达状态的信息。

## 8.6 减少动态效果矩阵

依据 `prefers-reduced-motion: reduce`。**逐模块降级，而非全局关闭**——反馈必须保留，运动必须移除。

| 模块 | 默认动效 | reduced-motion 替代 |
|---|---|---|
| M1 灵龛光点 | 漂浮 + 呼吸 + 鼠标跟随 + 聚拢 | **完全静态**：一次性绘制固定分布，**不启动 RAF**；提交/结果改用文字提示（`正在读取…` / `已读取完成`）与容器描边变化 |
| M1 光点聚拢 | 480ms 收拢 | 无位移；改为容器边框 1px → 2px 瞬时变化 + 文字提示 |
| M2 结果入场 | 位移 8px + 淡入 + 级联 | **仅淡入**（120ms），取消位移与缩放，级联延迟压为 0 |
| M2 数据格级联 | 60ms stagger | stagger = 0，全部同时淡入 |
| M3 列表入场 | 逐项 stagger | 整体淡入 120ms；筛选重排无过渡 |
| M4 抽屉滑入 | translate 320ms | **无位移**，直接显示 + 120ms 淡入 |
| M5 条目入场 | 逐条 stagger | 整体淡入 120ms |
| M5 Tab 切换 | FLIP 位移 | 无位移，仅淡入淡出 120ms |
| F3 生成器 | scale 弹入 | 无缩放，仅淡入 120ms |
| F3 生成成功 | scale + 淡入 | 仅淡入 160ms |
| F2 确认对话框 | scale 弹入 + 遮罩淡入 | 无缩放，仅淡入 120ms；遮罩瞬时出现 |
| F2 管理页入场 | 卡片 stagger 60ms | stagger = 0，全部同时淡入 120ms |
| F1 检查结果 | 结果卡淡入上移 8→0 | 仅淡入 120ms，取消上移 |
| F1 Toast 复制反馈 | 升入 200ms | 仅淡入 120ms |
| 骨架屏高光 | 1200ms 扫光循环 | 停止扫光；改为静态 6% 亮度呼吸（2400ms 循环）或完全静态 |
| 滚动定位 | `behavior: 'smooth'` | `behavior: 'auto'`（瞬时跳转） |
| Toast | 升入 200ms | 仅淡入 120ms |

**不受 reduced-motion 影响**（必须保留）：焦点环、错误提示、状态文案变化、加载指示器（旋转可改为静态「…」或进度文字）。

**用户偏好开关**：站点提供一个显式开关「减少动效」，与系统偏好取**更严格者**（系统已开 → 强制静态；系统未开但用户手动开启 → 静态）。开关持久化在 `localStorage`（键 `uos:reduced-motion`）。

| 场景 | 播报 |
|---|---|
| 页面加载 | 页面标题 + 首个区块标题 |

## 8.9 已知限制与豁免

| 项 | 说明 | 计划 |
|---|---|---|
| 灵龛 Canvas | 纯装饰，`aria-hidden="true"`，不承载信息 | 无豁免风险 |
| 分享卡片图片 | 图片内容对屏幕阅读器不可读 | **缓解**：图片 `alt` 自动生成等价文本摘要（用户名、称号、关键数值）；同时提供纯文本复制出口（§F3.8） |
| 横向滑动的代表卡 | 移动端横滑对部分用户不直观 | 提供页码点 + 左右按钮（可聚焦）+ 键盘左右键 |
| 拖动条 | 移动端抽屉顶部视觉拖动条 | **仅为视觉提示**，不实现拖拽；关闭由按钮提供（避免只靠拖拽的无障碍问题） |
| 短时间大量 Toast | 连续操作时可能来不及阅读 | Toast 停留 3s 且可悬停暂停；重要信息另有持久内联条 |

## A.4 一页速查（实现时最常查的 14 条）

1. 未知 ≠ 0；未知态 = 灰字 + 虚线 + `?`，不隐藏整格。
2. 全站唯一的红色 `--color-alert-stop` 只用于硬错误。
3. 休眠标签永不用于评价人，主语永远是仓库。
4. 阈值、称号规则必须在界面上可查（§5.5）。
5. 每张卡片、每条榜单、每张分享图都带「读取于 …」。
6. 限流绝不显示为空结果集（E01 vs E18 必须视觉可分）。
7. 分享必须「预览 → 确认 → 生成」三步，且生成前列出「将公开」清单。
8. 抽屉/弹层：焦点进入、焦点还原、焦点圈定、`Esc` 关闭。
9. 筛选与排序是纯客户端操作，**不产生 loading 态**。
10. 动效时长取 §1.5 令牌；reduced-motion 逐模块降级，不全局关闭。
11. 查询行为**不上榜**；上榜只认「个人 + 公开 + Topic + 已核实 + 未隐藏」五项。
12. 隐藏仓库后，榜单、详情页、鉴定统计、分享图、社交预览全部失效（≤ 5 分钟）。
13. 主题是**配置**：界面上的主题名一律渲染解析后的值（§0.5.1），代码里不得出现字面量。
14. 充能等级是**派生**的：响应体只带计数，等级由共享层算出；计数未知时等级显示 `? 未知`，不是「未启封」（§M2.5）。
