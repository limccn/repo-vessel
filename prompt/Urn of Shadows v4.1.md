# 影之灵龛 Urn of Shadows

## 产品设计 v4.1：娱乐优先的轻量版

> **你的代码没有消失，只是进入了待机动画。**

---

## 一、这次怎么调整？

v4.0 的重点是“轻量仓库整理工具”，v4.1 将它调整为：

> **一个可以输入 GitHub 用户名，看看自己的公开仓库到底“睡得有多安详”的趣味网站。**

用户不需要带着“我要整理仓库”的目的进来，也不需要完成任务。打开网站，输入用户名，看到一份有趣但基于事实的结果；如果觉得好玩，就分享一下。如果想进一步查看仓库，也有简单的工具入口。

### 产品优先级

```text
第一优先级：好玩、看得懂、愿意分享
第二优先级：信息真实、边界清楚、用户可控
第三优先级：提供基础仓库查看与 Fork 溯源
```

### 不变的边界

- 只处理**个人账户拥有的公开仓库**；
- 不访问私有仓库，不扫描组织仓库；
- 不读取仓库代码内容；
- 网站只读，不修改、归档或删除 GitHub 仓库；
- 不做社区、评论、打卡、任务或习惯养成；
- 榜单中的仓库必须满足公开收录规则，所有者可以认领并隐藏。

# 二、产品定位

## 2.1 一句话介绍

> **查一查，你的 GitHub 里住着多少沉睡的灵魂。**

影之灵龛是一个 GitHub 公开仓库趣味浏览网站。

用户输入用户名，就能看到：

- 哪些仓库已经很久没有推送；
- 哪个仓库沉睡时间最长；
- 哪个沉睡仓库仍然最受欢迎；
- 自己的公开 Fork 大致来自哪里；
- 一张可分享的“灵龛鉴定卡”。

如果用户愿意，还可以给自己的公开仓库添加 `urn-of-shadows` Topic，让它有机会出现在本站公开榜单。

## 2.2 核心体验

产品不把用户往“清理”上推，而是提供三种轻体验：

### 体验 A：看看自己

> “我的 GitHub 到底藏了多少个旧坑？”

输入用户名，即刻看到自己的公开仓库概览和趣味称号。

### 体验 B：看看榜单

> “还有谁的仓库睡得比我久？”

浏览由所有者通过 Topic 标记的公开仓库，看看沉睡项目的各种故事线索。

### 体验 C：给仓库一个称号

> “这个项目不删了，给它放进灵龛吧。”

用户手动添加 Topic，仓库被发现后进入候选池；不需要写墓志铭，也不需要注册产品。

# 三、产品气质：不是墓地，是代码的休息室

## 3.1 世界观

影之灵龛不是一座批判开发者的墓地，而是一间安静又有点幽默的**代码休息室**。

这里的仓库可能：

- 曾经只是一次好奇；
- 在一个周末被热情创建；
- Fork 以后等着“有空再看”；
- 虽然多年未更新，却仍有人 Star；
- 已经完成自己的使命，不需要继续变化。

产品不替作者定义原因，只负责把公开信息变得有趣。

### 文案基调

| 可以这样说 | 尽量不要这样说 |
|---|---|
| `已进入深度待机` | `项目已经失败` |
| `最后一次推送在 892 天前` | `作者遗弃了它` |
| `你的 Fork 和上游暂时走散了` | `你的 Fork 没用了` |
| `这颗星星还亮着` | `你错过了成为明星项目的机会` |
| `适合再看一眼` | `你应该清理它` |

### 一句产品承诺

> **我们只讲数据能证明的事，梗的部分由你自己理解。**

# 四、三个入口：每一个都可以单独完成

## 入口一：输入用户名，看看自己的公开仓库

这是最主要的入口。

```text
输入 GitHub 用户名
        ↓
读取个人账户拥有的公开仓库
        ↓
生成轻量「灵龛鉴定」
        ↓
查看仓库 / 分享结果 / 直接离开
```

- 不需要登录；
- 不需要授权；
- 不会因为被查询就自动上榜；
- 查询结果不是对开发者能力或活跃度的评价。

## 入口二：手动添加 Topic，让仓库入龛

```text
用户在 GitHub 手动添加 urn-of-shadows
        ↓
本站发现并核实仓库
        ↓
符合条件时进入公开候选池
        ↓
根据数据参与相应榜单
```

- 不需要先注册本站；
- 添加 Topic 表示用户希望该个人公开仓库可以被本站收录；
- GitHub 搜索和本站更新存在延迟，不保证立即发现；
- 用户可以检查收录状态，也可以退出。

## 入口三：登录并认领已收录仓库

```text
看到自己的仓库
        ↓
点击「这是我的仓库」
        ↓
使用 GitHub 登录
        ↓
验证当前所有者
        ↓
隐藏或恢复本站展示
```

- 认领只用于管理本站展示；
- 不授予网站修改仓库的能力；
- 不认领也可以使用查询和浏览功能。

# 七、灵龛鉴定：娱乐的核心

## 7.1 结果页结构

用户输入用户名后，页面滚动到结果区：

```text
@username 的灵龛鉴定
────────────────────────────
本次读取到 36 个个人公开仓库

你的称号：时光收藏家

最长沉睡          仍有余烬
1,024 天          3 个仓库

公开 Fork         已经归档
12 个             4 个

[查看我的仓库] [生成鉴定卡]
────────────────────────────
```

### 结果说明

- 所有数字仅基于本次成功读取的个人公开仓库；
- 数据不完整时，明确提示“本次结果可能不完整”；
- 不读取私有仓库，也不统计组织仓库；
- 不把别人的用户名查询结果自动加入榜单。

## 7.2 趣味称号

称号由简单、公开的规则生成，用于娱乐，不评价用户。

| 称号 | 建议触发条件 | 文案 |
|---|---|---|
| **时光收藏家** | 存在至少一个超过 3 年未推送的仓库 | 有些想法，需要一点时间发酵。 |
| **灵感播种员** | 公开原创仓库较多 | 你在不同的地方种下过很多想法。 |
| **Fork 远航家** | 公开 Fork 在仓库中占比较高 | 你曾沿着许多有趣的航线出发。 |
| **余烬守护者** | 存在沉睡较久、仍有 Star 的仓库 | 安静下来之后，它仍被人记得。 |
| **轻装旅人** | 本次没有找到符合沉睡条件的仓库 | 你的公开仓库看起来相当轻盈。 |
| **神秘访客** | 数据不足，无法生成其他称号 | 有些故事，暂时还没有被看到。 |

### 称号规则

- 每次查询最多显示一个主称号；
- 同时满足多个条件时使用固定优先级，避免随机改变结果；
- 点击称号旁的 `?` 可查看依据；
- 不给用户打分或排名；
- 不根据仓库数量推断工作量、能力或成败。

## 7.3 三个代表仓库

结果区展示三张小卡片：

### 卡片 A：睡得最久

> **深度待机冠军**  
> `alice/old-project`  
> 上次推送：1,024 天前。

### 卡片 B：星光仍在

> **余烬最亮**  
> `alice/old-library`  
> 许久未推送，仍有 128 颗 Star。

### 卡片 C：来自远方

> **远行的 Fork**  
> `alice/some-fork`  
> 来自另一个公开项目。

如果没有符合条件的仓库，就用友好的空状态代替：

> 暂时没有找到这一类仓库。

不为了凑齐卡片而编造结果。

# 八、仓库卡片：给数据一点表演空间

## 8.1 卡片内容

每张卡片保留真实信息：

- 仓库名称和描述；
- 最后推送日期及相距天数；
- Star、Fork；
- 原创 / Fork；
- 主要语言；
- 是否已归档；
- 是否带有指定 Topic。

## 8.2 趣味状态标签

标签由明确规则生成，点击可查看解释。

| 标签 | 示例规则 | 说明 |
|---|---|---|
| `刚刚安静` | 6–12 个月未推送 | 并不代表停止维护 |
| `深度待机` | 1–3 年未推送 | 只基于最后推送时间 |
| `时间胶囊` | 超过 3 年未推送 | 不代表项目已经失效 |
| `余烬未熄` | 沉睡且 Star 达到设定门槛 | Star 不代表当前仍被使用 |
| `远行的 Fork` | 仓库是 Fork | 不推断 Fork 的用途 |
| `已归档` | GitHub 返回已归档状态 | GitHub 状态，不是本站操作 |

阈值可在产品上线前确定，并在界面中公开。

### 详情按钮

- `看看详情`
- `打开 GitHub`

对已收录的仓库额外显示：

- `这是我的仓库`

# 九、榜单：围观的是仓库，不是评价人

## 9.1 榜单原则

榜单只展示：

- 个人账户拥有的公开仓库；
- 带有 `urn-of-shadows` Topic；
- 已被本站发现并核实；
- 未被当前所有者隐藏。

页面顶部始终说明：

> 排名仅来自本站已发现并核实的仓库，不代表整个 GitHub。

## 9.2 最长沉睡榜

### 榜单标题

> **最长沉睡榜**

### 副标题

> 它们没有走远，只是很久没有推送。

### 排序

按最后推送时间从早到晚。

### 卡片文案

```text
#01

alice / ancient-side-project

已沉睡 2,048 天
最后推送：2021-03-22

⭐ 42   Fork 7

[查看详情] [分享]
```

**数据说明：**最后推送不等于最后提交，也不代表作者本人不活跃。

## 9.3 余烬未熄榜

### 副标题

> 有些仓库安静了，星星还亮着。

### 入榜条件

- 超过设定时间未推送；
- Star 达到最低门槛；
- 满足公开收录条件。

### 排序

默认按 Star 数排序，用户可切换为最后推送时间。

### 趣味表达

> 这只灵龛里，还有 256 颗星光。

## 9.4 Fork 漂流榜

### 副标题

> 有些 Fork 出发以后，就留在了自己的时间线上。

### 第一版轻量定义

展示符合收录条件的 Fork，并按沉睡时间排序。

仓库详情中展示可获得的来源线索。对于个人公开上游，可在技术条件允许时补充活跃和归档状态；对于组织上游，不进一步读取。

**为什么不把领先 / 落后提交数作为第一版主排序？**

该数据需要选定分支、进一步比较且可能不可用。它适合作为后续增强，但不应该让趣味榜单依赖一个昂贵或容易缺失的数据项。

### 文案示例

> 从 `original/project` 出发，停在了 892 天前。

如果来源信息不可用：

> 这段旅程的起点，暂时无法确认。

## 9.5 榜单不做什么

- 不展示开发者“最懒排行”；
- 不按“浪费工时”排序；
- 不估算失败概率；
- 不提供评论、投票或围攻式互动；
- 不自动提醒或 @ 仓库所有者。

# 十、Fork 溯源：作为有趣的“来路卡片”

工具能力保留，但表达上更轻。

## 10.1 详情卡片

```text
它从哪里来？

你的 Fork
alice/project
最后推送：892 天前

        ↓ 来自

来源仓库
original/project
状态：可访问
最后推送：45 天前

[打开来源仓库]
```

如果数据足够，可在后续增加：

```text
你们现在走到了哪里？

在选定分支下：
你的 Fork 领先 2 个提交
你的 Fork 落后 18 个提交

数据更新时间：……
```

### 对组织上游的处理

如果来源属于组织：

> 这个 Fork 来自一个组织仓库。本站不读取组织仓库信息。

如个人 Fork 的公开元数据已经包含来源名称或链接，可仅展示该已有线索；不进一步请求、扫描组织仓库，也不展示其活动状态或比较结果。

## 10.2 不做自动建议

不根据 Fork 数据直接提示“删除”“同步”或“上游已修复”。

产品最多提供：

> 想继续了解？可以前往 GitHub 查看双方仓库。

# 十一、入龛体验：一个 Topic，一次动作

## 11.1 页面说明

### 标题

> **想让你的仓库住进灵龛？**

### 三步说明

1. 打开你自己的**个人公开仓库**；
2. 在 GitHub 仓库页面手动添加 Topic：`urn-of-shadows`；
3. 等待本站发现，或粘贴仓库链接检查状态。

### 用户提示

> 添加这个 Topic 表示你希望该公开仓库可以被影之灵龛收录和展示。  
> 搜索与更新可能有延迟；你可以随时移除 Topic，或认领后隐藏。

### 主按钮

```text
[复制 Topic]
```

按钮点击后反馈：

> 已复制，去 GitHub 给仓库贴上它吧。

## 11.2 检查收录状态

```text
[ 粘贴公开仓库链接                  ] [检查]
```

结果可能为：

- `已经入龛`；
- `已发现 Topic，等待下一次收录核实`；
- `没有找到 urn-of-shadows Topic`；
- `本站只收录个人公开仓库`；
- `当前无法确认仓库状态，请稍后再试`。

不要求用户登录才能检查公开状态。

# 十二、认领与退出：要容易，也要说清楚

## 12.1 认领入口

在公开仓库详情中显示：

> **这是你的仓库吗？**  
> 登录 GitHub 后，可以管理它在本站的展示。

按钮：

```text
[登录并认领]
```

认领时验证：

1. 当前登录用户是仓库所有者；
2. 所有者是个人账户；
3. 仓库当前为公开状态；
4. 仓库已被本站收录。

## 12.2 认领后

用户可以：

- 隐藏本站展示；
- 查看本站显示的数据；
- 在符合收录条件时恢复展示；
- 查看如何移除 Topic；
- 撤销登录或删除本站管理记录。

## 12.3 退出展示

### 方式一：本站隐藏

认领后点击 `隐藏此仓库`。

即使 Topic 仍存在，本站也不应在下一次扫描时重新展示它。

### 方式二：GitHub 移除 Topic

用户手动移除 `urn-of-shadows`，本站在下次核实发现后下架。

### 无法登录或无法认领时

提供一个**下架申请入口**，允许用户提交仓库链接及说明。产品需设计人工或其他可验证的处理方式，不能要求所有用户必须完成 GitHub 登录才能提出异议。

## 12.4 缓存与状态变化

- 如果已知仓库变为私有、转入组织或不再符合条件，应下架；
- 状态无法重新确认时，应暂时隐藏；
- 分享页和本站生成的图片缓存也应随下架失效；
- GitHub 搜索发现、定期核实和外部平台缓存都有延迟，不能承诺已被第三方保存的内容全部消失。

```text
│     数据基于个人公开仓库   │
└─────────────────────────────┘
```

### 操作

- `生成图片`
- `复制结果链接`
- `重新选择卡片风格`

查询他人用户名也能看到公开数据，但分享前应明确显示将公开的用户名和字段。产品不自动发布、不自动通知或 @ 对方。

## 13.2 仓库卡片

适合分享一个已经公开收录的仓库：

> **时间胶囊 · 1,024 天**  
> `alice/old-project`  
> “最后一次推送，还停在那个春天。”

最后一句是基于日期的氛围化表达，不暗示项目发生过什么。

## 13.3 分享控制

- 分享前预览；
- 用户主动点击生成；
- 不包含私有仓库数据；
- 不推断项目失败原因；
- 不使用“浪费了多少小时”等估算；
- 不自动 @ 仓库所有者；
- 公开仓库下架后，本站可控的分享页面和缓存同步失效。

# 十四、视觉与动效

## 14.1 视觉方向

**关键词：幽光、代码碎片、安静、好玩。**

区别于传统“墓地”视觉：

- 不使用墓碑、骷髅、坟土作为主元素；
- 使用原创抽象容器，容器中漂浮代码碎片；
- 用柔和幽光代替恐怖氛围；
- 让趣味感来自文案和状态，而不是嘲笑用户。

## 14.2 色彩

| 用途 | 建议 |
|---|---|
| 背景 | 深灰蓝、近黑 |
| 主色 | 青绿色幽光 |
| 辅色 | 暗金、柔紫 |
| 正文 | 柔和米白 |
| 数据强调 | 高对比亮色，但不过度刺眼 |
| 异常提醒 | 琥珀色 |

## 14.3 动效

- 输入后：灵龛中的光点短暂聚拢；
- 查询中：显示实际加载状态，不假装鉴定比请求更久；
- 结果出现：卡片轻微浮现；
- 分享成功：光点闪烁一次；
- 减少动态效果开启时：使用静态反馈。

# 十五、数据与权限边界

## 15.1 我们读取什么

第一版只读取必要的公开信息，例如：

- 个人公开仓库名称、描述、语言；
- Star、Fork 数；
- 最后推送时间；
- 创建时间；
- 是否为 Fork；
- 是否已归档；
- Topic；
- 在允许范围内可获得的 Fork 来源信息。

**不读取：**

- 私有仓库；
- 组织仓库；
- 仓库代码内容；
- 用户本地文件；
- 与产品无关的个人资料。

## 15.2 GitHub 登录

登录只用于：

- 确认 GitHub 身份；
- 认领当前用户自己的已收录仓库；
- 管理本站展示。

不申请私有仓库访问权限或仓库写权限。

具体认证方式、公开 API 配额与字段可用性，需在开发时按 GitHub 当前文档核实。

## 15.3 数据表达

| 字段 | 产品口径 |
|---|---|
| 沉睡天数 | 根据最后推送时间计算 |
| 仓库数量 | 本次成功读取的个人公开仓库数 |
| Star / Fork | 读取时的公开统计，标注更新时间 |
| Fork 来源 | 在可获得且符合范围时展示 |
| 数据未知 | 明确显示未知，不当作零 |

# 十六、MVP 范围

## 必做

### 娱乐体验

1. 首页用户名输入；
2. 个人公开仓库查询；
3. 灵龛鉴定结果；
4. 固定规则的趣味称号；
5. 三张代表仓库卡片；

### 公开榜单

8. 余烬未熄榜；
9. Fork 漂流榜；
10. 仓库详情和 GitHub 链接。

### 入龛与控制

- GitHub 写操作；
- Agent、MCP；
- 自动代码提取；
- AI 自动判断项目价值；
- 工作时长估算；
- 年度报告。

# 十七、成功指标

娱乐优先，但不以“让用户反复回来”为前提。

| 目标 | 观察指标 |
|---|---|
| 用户愿意尝试 | 首页访问到发起查询的比例 |
| 用户能看到结果 | 查询成功率、结果加载时间 |
| 结果有趣 | 结果页分享卡生成率 |
| 内容自然传播 | 分享链接的有效访问量 |
| Topic 入口有吸引力 | Topic 复制次数、符合条件的收录仓库数 |
| 用户能控制展示 | 认领与隐藏成功率 |
| 产品保持可信 | 误收录投诉、下架处理时间、状态核实失败率 |

不把日活、连续使用天数或榜单停留时间作为主要目标。

# 十八、最终体验总结

用户可以只花几十秒：

```text
打开网站
→ 输入 GitHub 用户名
→ 看看自己的灵龛鉴定
→ 如果觉得有趣，分享
→ 离开
```

也可以只做一个动作：

```text
在自己的公开仓库添加 urn-of-shadows
→ 等待它被发现
```

或者只做一次管理：

```text
看到自己的仓库
→ 登录认领
→ 隐藏
→ 离开
```

> **影之灵龛 v4.1 不要求用户整理过去，也不催促用户重启项目。**  
> **它只是让那些安静的公开仓库，以一种有趣、温和、可退出的方式被看见。**
